# 验收 / 自查 / 审计技能（抄本纪元）

审计的最高原则：**实现服从文档**。发现"实现超出文档"，补文档或删实现（由主代理裁决方向）；发现"实现少于文档"，列缺口。

## 1. 功能验收（每个功能完成后必做）

对照清单逐项勾选，全部通过才算完成：

1. **文档依据**：实现对应的文档条款号明确（如"11 §3.1 优势/劣势"）；
2. **无头测试**：`godot --headless --path game -s tests/run.gd` 全绿，且新行为有对应断言；
3. **铁律扫描**（grep 级别）：
   - `grep -rn "extends Node\|Input\.\|@onready" game/core/` → 必须为空；
   - `grep -rn "randi()\|randf()" game/core/`（rng.gd 除外）→ 必须为空；
   - `grep -rn "Board\." game/shell/ | grep -v "read\|get_"` → shell 不得写 Board；
4. **事件流完整性**：新行为是否产出事件（历史卷轴可追溯）？写入是否带溯源？
5. **双壳一致性**（涉及遭遇时）：同一遭遇两壳各跑一遍，事件流逐字节一致（数值、判定、结果）。

## 2. 系统自查（每周或里程碑前）

| 系统 | 对照文档 | 检查点 |
|---|---|---|
| 状态板/存档 | framework/07 | 六类变量范围、命名空间权限、快照时机与迁移链 |
| 分支图 | framework/08 + tech/02 §12 | packlint V1~V13 全绿 |
| 遭遇六态 | framework/09 §1 | 进出条件、整备/快捷栏/托管、单局退出（保存并回主屏=遭遇重打） |
| 双形态 | framework/09 §8 + 04 | 单局内无切换入口、竖屏同屏 ≤8、三段呼吸比例 |
| 手势 | framework/12 | 词表参数、冲突消解、**每个手势有按钮等价路径** |
| 规则 | framework/11 | D20/暴击/优势劣势/豁免/同伴/死亡豁免三局两胜 |
| 效果 | tech/04 | base→add→mul→override→clamp 管线顺序、效果溯源 |
| 商业化 | framework/06 | 权利只读、禁区（不卖骰子/数值/不破免费分支）、锁定态呈现 |
| 界面闭环 | 04 §5 | 九类界面入口/出口双列检查 |

## 3. 发布审计（每次发版前）

1. **packlint**：`game/tools/packlint.gd` 对全部内容包跑 V1~V13，全绿；
2. **bot 仿真**：`game/tools/simulate.gd` 跑通 campaign01 全部结局（TP1 出口）；
3. **双壳抽查**：随机 3 场遭遇两壳比对事件流；
4. **存档兼容**：上一版本存档加载 + 迁移链跑通；
5. **付费禁区人工复核**：新增商品/权利路径逐条过 06 §4 四条铁律；
6. **迭代双轨合规**：本次发版属内容轨还是运营轨？内容轨是否走了完整管线？运营轨是否未动内容图、未回收已获权利？

## 4. 审计报告格式

```
## 审计报告 · <范围> · <日期>
结论：通过 / 有条件通过 / 不通过
### 通过项（附证据：测试输出/日志/截图）
### 缺口（实现 < 文档）：[条款号] 缺口描述 → 建议修法
### 超出（实现 > 文档）：[位置] 超出描述 → 建议：补文档 or 删实现
### 风险与跟进项
```

## 5. 修复纪律

- 缺口修复：按文档实现；
- 超出处理：**默认回文档补写**（与用户对齐过的先例：暴击、属性点），无法补写则删实现；
- 审计不通过不得提交合并；有条件通过必须在提交信息中列明未决项。
