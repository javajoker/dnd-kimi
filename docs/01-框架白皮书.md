# 游戏框架白皮书

> 版本：v0.1（草案）
> 状态：框架设计冻结前评审稿
> 范围：本白皮书只定义“游戏框架”——即能承载任意故事线、战役与子游戏的结构骨架。具体世界观、主线故事、子游戏内容不在本文范围内，另行立项。

---

## 1. 愿景与定位

一款以桌面角色扮演（D&D 式）体验为核心的手游：

- **一台引擎装所有故事**：框架与内容彻底分离，新剧情、新战役、新子游戏 = 新内容包，不改动框架本身；
- **边发布、边开发、边迭代**：上线后即可持续投放新故事分支与内容包，框架对内容向后兼容；
- **一部手机两种玩法**：同一套遭遇内核支撑“横屏·空间战役”与“竖屏·时间战役”两种形态；战役模式在进入时由玩家选择或由主线强制指定，数据零差异。

## 2. 设计支柱

| 支柱 | 含义 | 反例（我们不做） |
|---|---|---|
| 框架与内容解耦 | 剧情、关卡、道具全部是内容包数据；框架只提供规则与状态机 | 为新剧情改引擎 |
| 失败即分支 | 检定失败不是终局，而是通往另一条故事路径 | 失败=读档重来 |
| 状态板唯一真相 | 一切分支由世界状态板驱动，剧情节点只监听状态板 | 剧情之间互相硬编码调用 |
| 呈现与逻辑解耦 | 单局逻辑不认识呈现形态，横屏 / 竖屏只是两套渲染与节奏包装 | 两个模式两套玩法逻辑 |
| 内容可持续投放 | 内容包有统一结构约定与版本规范，可增量发布 | 每次更新发整包 |

## 3. 总体结构：五层漏斗 + 一台引擎

```
L0  纪元（Epic）        ── 世界背景、终局威胁、世界状态板的最高层归属
 └─ L1 战役（Campaign）  ── 一本“战役书”：一张完整的故事节点图集合
     └─ L2 故事线（Arc）  ── 一幕剧情：5~15 个节点的有向图
         └─ L3 任务/事件  ── 触发条件 + 目标 + 结算的最小剧情单元
             └─ L4 遭遇   ── 单局游戏：迷宫探索 / 战斗 / 对话 / 休整
```

横切五层的引擎是**世界状态机**（见 §4）。所有层级的所有分支，都通过读写世界状态板发生。

## 4. 世界状态机（World State）

### 4.1 状态板的六类变量

| 变量类型 | 示例 | 驱动什么 |
|---|---|---|
| 剧情旗标 Flag | `救了铁匠 = true` | 解锁 / 关闭故事节点 |
| 声望 Reputation | 某阵营 +2 | 阵营商店、NPC 态度、声望边 |
| 时间钟 Doom Clock | 献祭仪式 7/10 格 | 时间边、坏结局收束 |
| 物品持有 Inventory | 持有「碎裂的星图」 | 道具边、合成、图鉴 |
| 羁绊 Bond | 某队友好感 60 | 个人任务线、离队事件 |
| 抉择倾向 Alignment | 守序 ↔ 混乱 滑动值 | 结局分型 |

### 4.2 铁律

**游戏内任何系统都不直接改剧情，只写状态板；剧情节点只监听状态板。**

这一条解耦换来三件事：

1. “失败也能继续”在结构上成立（检定失败只是写了不同的旗标）；
2. 存档 = 状态板快照，天然支持云同步与多周目；
3. 内容包之间通过状态板对话，彼此不需要知道对方的存在。

### 4.3 命名空间

变量按内容包划分命名空间（如 `campaign01.救了铁匠`），保证多个内容包共存时互不污染；全局变量（声望、倾向）归框架层管理。

## 5. 分支模型：故事有向图

### 5.1 节点与边

故事线（L2）是一张有向图：节点是场景 / 事件，边是通路条件。边共五种：

| 边类型 | 含义 | 示例 |
|---|---|---|
| 选择边 | 玩家明示选择 | 救 / 不救 / 欺骗 |
| 检定边 | D20 判定，成功与失败各走一条 | 撬锁失败 → 警报 → 潜入战 |
| 道具边 | 持有指定物品才显形 | 有星图 → 密道节点出现 |
| 时间边 | 时间钟到格自动触发 | 仪式完成 → 坏结局支线 |
| 声望/倾向边 | 隐形门槛，事后可察觉 | 声望足够 → 阵营求助选项 |

### 5.2 分支的性质

- **分支不是树，是状态板上长出来的可达图**：同一本战役书，不同周目因旗标不同，实际展开的子图可以只有约 60% 重叠；
- **失败不终结**：所有检定边必须有“失败路”，且失败路也要有戏；
- **收束与开放并存**：关键节点允许多路汇入（避免分支爆炸），但汇入时携带的旗标不同，后续待遇不同。

## 6. 单局遭遇状态机（L4 内核）

单局是玩家实际“玩”的单元。逻辑层是一台与呈现完全无关的状态机：

```
进场 → 探索态 ⇄ 发现态（检定 / 拾取 / 陷阱）
         ↓ 触发                ↓ 触发
      战斗态（先攻→回合循环→结算）  对话态（选项 / 检定）
         ↓                        ↓
      结算态（经验 / 战利品 / 写状态板）→ 休整态 → 出场
```

约定：

- 所有数值、判定、AI、战利品 roll 只发生在逻辑层；
- 逻辑层对外只输出**事件流**（例：“你对兽人造成 14 点伤害”“检定成功：感知 18”）；
- 事件流是渲染层唯一的输入，也是日志、回放、成就系统的唯一输入。

## 7. 双模式呈现：横屏空间战役 / 竖屏时间战役

### 7.1 模式是战役的属性，不是屏幕姿态

呈现模式不由手机旋转决定，而是**战役（内容包）的声明属性**：

- 每本战役书声明自己的呈现模式：`横屏空间` / `竖屏时间` / `双模式可选`；
- **进入战役即一次分支选择**：双模式战役在入口处向玩家提供模式选择，选择结果写入状态板；单模式战役由主线设计强制指定——强制本身就是叙事手段（演出密集的战役强制竖屏时间流，大战场强制横屏空间盘）；
- 模式在单场战役期间锁定，不做中途切换；
- 同一战役若以双模式发布，另一模式成为重玩路径，直接服务多周目与分支收集。

### 7.2 两种战役形态

| | 横屏·空间战役 | 竖屏·时间战役 |
|---|---|---|
| 玩法隐喻 | 把战场“摊开”：格子、站位、视野 | 把故事“流过去”：多房间、按节拍推进 |
| 遭遇结构 | 空间遭遇：战术格地图，自由移动 | 时间遭遇：房间序列，逐间解锁 |
| 布局 | 空间分区：中央主视野 + 左右栏 + 上下缘 | 时间分区：主视野 / 操作台，高度随情境“呼吸” |
| 战斗呈现 | 战术格、站位、弹道线 | 竖向战场 / 智能镜头 / 信息流战报 |
| 掷骰 | 右侧骰子盘，关键判定全屏演出 | 骰子托盘分级演出（普通快掷 / 关键全屏） |
| 信息策略 | 同时并列呈现 | 同一像素按瞬间切换用途 |

### 7.3 一核两壳铁律

- **数据零差异**：同一场遭遇由同一台状态机驱动，两种形态只是两套渲染与节奏包装，数值、判定、结果逐字节一致；
- **渲染层无逻辑**：任何规则、数值、判定不得进入渲染层；
- **事件流唯一输入**：两套渲染器消费同一份事件流，日志、回放、成就、历史卷轴同样消费它。

## 8. 道具与收集体系

道具在框架中有四重身份，按稀有度递进：

1. **数值**：影响单局强度（武器、护甲、消耗品）；
2. **检定修正**：影响检定边通过率（工具、护符）；
3. **分支钥匙**：打开道具边，改变故事图形状（星图、印戒、信物）；
4. **图鉴 / Lore**：集齐系列解锁背景条目与隐藏内容入口。

收集不是挂件玩法，而是**改变分支拓扑的手段**，直接服务于多周目与内容包扩展。

## 9. 元循环（Meta Loop）

```
玩一局遭遇（L4）
  → 结算写入世界状态板（旗标 / 声望 / 时钟 / 物品 / 羁绊）
    → 触发器扫描：哪些故事节点被点亮 / 熄灭（L2 / L3）
      → 战役地图更新，新入口出现（L1）
        → 时间钟推进，纪元走向结局分型（L0）
          → 玩家选择下一个入口，进入下一局
```

玩家眼中的体验是“我在冒险”；系统眼中的现实是“每场单局都是对世界状态板的一次写操作”。

## 10. 内容扩展模型：边发布边迭代

这是框架的生命线设计。

### 10.1 内容即数据

- 新故事线、新战役、新子游戏 = **内容包**：故事节点图 + 事件表 + 遭遇定义 + 物品表 + 文本资源；
- 框架发布后与内容包**版本解耦**：框架升级不破坏已发布内容包，新内容包声明其所需的最低框架版本。

### 10.2 子游戏

- 子游戏是**复用遭遇状态机、替换规则参数与表现包装**的内容包（例如：竞技场连战、解谜迷宫、经营休整所）；
- 子游戏通过状态板与主线互通（奖励写入状态板，门槛读取状态板），但可独立发布、独立更新。

### 10.3 投放节奏（产品层面约定）

1. 首发：框架 + 首个主线战役；
2. 其后以内容包形式持续投放：新故事分支 → 新战役 → 首个子游戏 → 更多内容包；
3. 每个内容包上线前必须通过：分支图完整性校验（无死路、无不可达节点）、状态板命名空间冲突检查。

## 11. 术语表

| 术语 | 定义 |
|---|---|
| 纪元（Epic） | 世界背景与终局威胁的最高叙事层 |
| 战役（Campaign） | 一本战役书，一个故事节点图集合 |
| 故事线（Arc） | 一幕剧情，5~15 个节点的有向图 |
| 遭遇（Encounter） | 单局游戏：迷宫 / 战斗 / 对话 / 休整 |
| 世界状态板 | 六类变量的集合，分支的唯一真相源 |
| 事件流 | 遭遇逻辑层输出的结果序列，渲染与日志的唯一输入 |
| 内容包 | 以数据形式发布的故事 / 战役 / 子游戏单元 |
| 时间钟（Doom Clock） | 推动终局压力的进度变量 |
| 战役模式 | 战役书声明的呈现形态：横屏空间 / 竖屏时间 / 双模式可选，进入时择定或强制 |
