# 产品需求文档（PRD）

> 版本：v0.1（草案）
> 关联文档：`docs/01-框架白皮书.md`
> 范围说明：本 PRD 定义产品与功能需求，不含技术方案；具体世界观与故事内容另行立项。

---

## 1. 产品概述

一款 D&D 式跑团体验的手游：玩家在五层叙事结构（纪元 → 战役 → 故事线 → 任务 → 单局遭遇）中冒险，一切抉择与检定写入世界状态板，驱动出每位玩家各不相同的故事分支。同一套遭遇内核支撑两种战役形态——横屏空间战役与竖屏时间战役，战役进入时择定模式或由主线强制指定。

**一句话定位**：一部手机，两种视角，一座可以一直长出新故事的跑团世界。

## 2. 目标用户

| 用户群 | 特征 | 我们给什么 |
|---|---|---|
| 跑团 / D&D 爱好者 | 熟悉 D20、检定、车卡 | 规则的仪式感：亲手掷骰、失败有戏、分支真实 |
| 剧情向 RPG 玩家 | 重视叙事与选择后果 | 有向图分支 + 状态板驱动的“选择算数” |
| 碎片时间手游用户 | 单手、通勤、短局 | 竖屏时间模式 + 单局 10~20 分钟节奏 |
| 收集 / 多周目玩家 | 追求图鉴与全分支 | 道具四重身份 + 分支拓扑差异 |

## 3. 核心体验目标

1. **掷骰的仪式感**：D20 是情绪高点，关键判定配全屏物理演出；
2. **选择真的算数**：玩家事后能追溯到“是那次选择导致了现在”；
3. **失败也有戏**：任何检定失败都通向一条有内容的路；
4. **双形态各擅其场**：横屏摊开空间、竖屏流动时间，进入战役时的模式选择本身构成一次分支决策；
5. **世界在生长**：每次更新都有新分支可玩，老存档持续有效。

## 4. 版本范围

### 4.1 v1.0（首发）：框架 + 首个主线战役

包含：

- 世界状态机（六类变量）与存档快照；
- 故事有向图运行时（五种边、触发器扫描）；
- 遭遇状态机全部状态（探索 / 发现 / 战斗 / 对话 / 结算 / 休整）；
- 横屏空间与竖屏时间双战役形态、战役入口模式分支与强制模式机制；
- 道具与图鉴系统（四重身份）；
- 内容包加载与版本兼容机制；
- 规则包机制（D20 最小核 + 轻规则包首发，F7）与商业化权利模型（F8）；
- 首个主线战役内容包（内容另行立项设计）。

### 4.2 v1.x（持续迭代）

- 新故事分支内容包；
- 新战役内容包；
- 首个子游戏内容包（复用遭遇状态机的变体玩法）。

### 4.3 明确不做（本期 Out of Scope）

- 联机 / 多人协作；
- UGC（玩家自制内容）编辑器；
- 付费数值体系（付费点设计待单独评审）；
- 世界观与具体故事内容（随内容立项另行产出）。

## 5. 功能需求

### F1 双模式呈现（战役级）

- F1.1 战役书声明呈现模式：横屏空间 / 竖屏时间 / 双模式可选；
- F1.2 双模式战役：进入战役时向玩家提供模式选择分支，选择结果记入状态板；
- F1.3 强制模式：主线设计可指定战役强制某一模式，入口不呈现选择，以叙事化方式呈现理由；
- F1.4 模式在单场战役期间锁定；另一模式可作为重玩路径；
- F1.5 同一战役双形态数据零差异：进度、数值、结果一致；
- F1.6 不提供游戏内的横竖屏旋转切换。

### F2 遭遇循环（单局）

- F2.1 状态机六态完整流转：进场 → 探索 ⇄ 发现 → 战斗 / 对话 → 结算 → 休整 → 出场；
- F2.2 回合制战斗：先攻顺序、移动 / 动作 / 附赠动作三段式行动经济；
- F2.3 检定系统：D20 + 修正 vs 难度，成功 / 失败双分支输出；
- F2.4 掷骰演出分级：普通检定快速结算，关键判定（死亡豁免、剧情拐点）全屏演出；
- F2.5 结算写入世界状态板：经验、战利品、旗标、声望、时间钟推进。

### F3 分支与触发

- F3.1 五种边全部可用：选择 / 检定 / 道具 / 时间 / 声望倾向；
- F3.2 失败即分支：每条检定边必须有失败路；
- F3.3 分支图校验工具（内容侧）：上线前检测死路与不可达节点；
- F3.4 玩家可追溯：日志中可回看关键旗标的来源事件。

### F4 道具与收集

- F4.1 道具四重身份：数值 / 检定修正 / 分支钥匙 / 图鉴；
- F4.2 图鉴集齐奖励：解锁背景条目与隐藏入口。

### F5 内容包机制

- F5.1 内容包独立发布、独立更新，无需升级框架；
- F5.2 内容包声明所需最低框架版本，框架向后兼容；
- F5.3 状态板按内容包划分命名空间，多内容包共存不冲突；
- F5.4 老存档在新内容包上线后持续有效，新内容可对老存档生效。

### F6 存档

- F6.1 存档 = 世界状态板快照；
- F6.2 支持多周目：重开战役时可选择保留部分收集进度（具体规则随主线设计定）。

### F7 规则包机制

- F7.1 规则深度为框架扩展轴：D20 最小核恒定，规则包承载属性模型 / 检定公式 / 行动经济 / 成长曲线等六要素；
- F7.2 战役声明所需规则包与最低版本，不同战役可使用不同规则深度共存；
- F7.3 首个主线采用轻规则包首发，支持后续内容包引入更深规则；
- F7.4 规则包独立版本化；老存档进行中战役可冻结在旧版本规则包下完成。

### F8 商业化能力

- F8.1 权利模型：权利为状态板全局变量，内容包声明解锁条件；购买 / 活动 / 成就均可点亮权利；
- F8.2 支持买断 / 内容包 DLC / 订阅 / 外观演出四种模式，可混合、逐版本调整；
- F8.3 付费禁区：不挂检定结果、不破坏免费分支完整性、不卖数值强度；
- F8.4 付费内容包与免费内容包走相同校验与界面闭环检查。

## 6. 里程碑（产品节奏）

| 里程碑 | 交付 | 出口标准 |
|---|---|---|
| M0 框架冻结 | 白皮书定稿、全部设计规范评审通过 | 白皮书 v1.0 签发 |
| M1 首个主线战役 | 世界观 + 主线战役内容设计完成 | 分支图校验通过、内部全流程可玩 |
| M2 首发 | v1.0 上线 | 框架 + 首战役稳定运行 |
| M3 首个子游戏 | 子游戏规则设计与内容包 | 验证“子游戏不动框架”的扩展承诺 |
| M4 持续运营 | 分支 / 战役内容包节奏化投放 | 形成稳定的内容更新管线 |

## 7. 成功指标（方向性，数值待运营立项细化）

- 双模式战役的模式选择分布，及所选模式与留存的相关性（验证“双形态”不是伪需求）；
- 单局完成率与单局时长分布（验证 10~20 分钟节奏假设）；
- 多周目开启率（验证分支差异是否被感知）；
- 内容包更新后的回流率（验证持续投放模型）。

## 8. 风险与开放问题

| 风险 / 问题 | 说明 | 建议处理方式 |
|---|---|---|
| 分支爆炸 | 有向图规模失控，内容产能跟不上 | 节点收束策略 + 校验工具；主线设计时定预算 |
| 竖屏大战场可读性 | 10+ 单位同屏时竖屏体验下降 | 关卡设计约束（多房间、少同屏）+ 智能镜头 |
| 双模式开发成本 | 两套渲染器等于每个功能做两遍呈现 | 交互规范前置冻结，M0 输出双模式组件清单 |
| 内容包兼容 | 老框架读不动新内容 / 新框架破坏老内容 | 版本声明与兼容测试纳入内容包上线 checklist |
| 规则深度取舍 | 已解决：框架内建规则包机制，多深度共存（F7）；首个主线采用轻规则 | 见 `05-规则系统框架.md` |
