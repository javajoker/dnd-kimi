# UI/UX 设计文档（框架级）

> 版本：v0.1（草案）
> 关联文档：`docs/01-框架白皮书.md`、`docs/02-PRD.md`
> 范围：本文档从框架角度定义全部界面的职责、结构与导航闭环——**每个界面都是世界状态板或事件流的一个视图**。不含视觉稿与像素规范（属原型阶段，另行立项）。

---

## 1. 设计原则

1. **一切界面是状态的视图**：界面不持有数据，只读世界状态板与事件流；界面的出现与消失由状态板变化驱动（与白皮书 §4 铁律一致）。
2. **闭环导航**：任何界面都有明确的来路（入口）与退路（出口），玩家永远不会停在死端。
3. **一个主焦点**：同屏只有一个主内容区，其余信息以边缘常驻或弹层形态存在。
4. **仪式感分级**：掷骰、关键剧情等情绪高点独占屏幕；常规操作轻量快速。
5. **框架先于内容**：本文档定义的界面结构对任何战役、故事线、子游戏内容包通用，内容只填充，不改结构。

## 2. 信息架构与导航闭环

九类界面构成完整游戏闭环：

```
                        ┌──────────────┐
                        │  ① 主屏（营地） │
                        └──────┬───────┘
        ┌──────────┬───────────┼───────────┬──────────┐
        ▼          ▼           ▼           ▼          ▼
   ② 战役入口   ⑤ 事件中心   ⑥ 背包图鉴   ⑦ 角色    ⑧ 历史卷轴
        │
        ▼ （双模式战役在此分支：横屏空间 / 竖屏时间；单模式直接进入）
   ③④ 遭遇（按战役声明形态渲染）
        │
        ▼
   ⑨ 结算界面 ──→ 回 ① 主屏 / 进入下一遭遇 / 查看 ⑧ 新增卷轴条目
```

约定：

- **主屏是唯一枢纽**：所有功能界面从主屏进入，操作结束回到主屏；
- **战役线是主动脉**：主屏 → 战役入口 → 遭遇 → 结算 → 主屏，一圈即一次元循环（对应白皮书 §9）；
- ⑧ 历史卷轴是唯一可从几乎所有界面以弹层形式唤起的界面（随时可查“为什么会这样”）。

## 3. 全局元素（跨界面常驻）

### 3.1 状态栏带

- 位置：各主界面顶部窄条；
- 内容：纪元时间钟（Doom Clock）总览格、队伍 HP 概览、当前战役进度；
- 铁律：**只放“看”的信息，不放“点”的高频操作**（顶部是拇指最难够的区域）；
- 例外交互：点时间钟 → 弹层显示时间边相关的逼近事件预告。

### 3.2 骰子系统

- D20 是全局元素，不属于任何单一界面；
- 演出分级：**普通检定**就地快速结算（≤0.5 秒）；**关键检定**（死亡豁免、剧情拐点、战役模式选择涉及命运判定时）全屏物理演出；
- “哪些判定算关键”由内容包标记，框架只提供两级演出容器。

### 3.3 弹层与抽屉

- 半屏弹层：角色卡、道具详情、时间钟预告——不打断当前界面情境；
- 底部抽屉：日志展开、对话选项——上滑展开、下滑收起；
- 全屏接管：仅限关键检定演出与战役通关演出。

## 4. 界面规格

以下每个界面按统一格式描述：目的 / 内容构成 / 核心操作 / 入口 / 出口。

### ① 主屏（营地）

- **目的**：游戏枢纽，元循环的起点与终点；呈现“世界现在的样子”。
- **内容构成**：
  - 中央：营地 / 世界图景（随纪元进度与旗标视觉变化——状态板的可视化）；
  - 可点亮位：战役入口（含进行中战役的“继续”）、事件中心（有未读触发时带角标）、背包图鉴、角色、历史卷轴；
  - 顶部：全局状态栏带；
  - 运营位：新内容包上架提示（框架级位，内容由投放决定）。
- **核心操作**：进入各功能界面；继续进行中的战役。
- **入口**：启动游戏；结算界面返回；各功能界面返回。
- **出口**：通往 ②⑤⑥⑦⑧。

### ② 战役入口

- **目的**：战役书的“封面”与**模式分支选择点**（框架修正后的核心界面）。
- **内容构成**：
  - 战役书卡：标题、所属纪元、简介、推荐等级、预计时长；
  - **模式分支区**（双模式战役）：两张形态卡并排——「横屏空间战役」（强调战术格、站位、大战场）与「竖屏时间战役」（强调多房间、叙事流、单手节奏），各附差异说明与推荐标签；选择即一次分支，写入状态板；
  - **强制模式**（单模式战役）：不呈现选择，以叙事化包装直接进入（例：“这一段记忆只能以碎片的方式回放”→ 强制竖屏时间）；
  - 多周目信息：已玩模式标记、本战役已探索分支占比（服务收集与重玩）。
- **核心操作**：选模式（若可选）→ 开始；查看分支收集进度。
- **入口**：主屏；事件中心的任务跳转。
- **出口**：进入遭遇（③或④）；返回主屏。

### ③ 遭遇 · 横屏空间形态

- **目的**：把战场摊开——空间感、站位、战术。
- **布局**（横屏五区）：

```
┌──────────────────────────────────────────┐
│ 上缘：队伍状态条 + 先攻顺序条（战斗时展开）   │
│ ┌─────────┬────────────────────┬───────┐ │
│ │ 左栏     │  中央主视野         │ 右栏  │ │
│ │ 行动轮盘 │  战术格地图          │ 骰子盘│ │
│ │         │  （探索/战斗共用镜头）│      │ │
│ └─────────┴────────────────────┴───────┘ │
│ 下缘：日志带（上滑展开半屏）                 │
└──────────────────────────────────────────┘
```

- **核心操作**：左栏选动作 → 中央点目标格 → 确认；右缘掷骰；下缘查日志。
- **入口**：战役入口（横屏形态）；战役中下一遭遇。
- **出口**：结算界面⑨；紧急撤退（若有该边）→ 事件中心。

### ④ 遭遇 · 竖屏时间形态

- **目的**：把故事流过去——多房间逐节拍推进，单手可达。
- **布局**（三段式，高度随情境呼吸）：

```
┌─────────────────────┐
│ ① 状态栏带（8%）      │ 队伍头像 + HP 环 + 先攻序（战斗时）
├─────────────────────┤
│ ② 主视野（55~62%）    │ 当前房间 / 遭遇场景 / 对话演出
├─────────────────────┤
│ ③ 操作台（30~37%）    │ Tab：行动 / 骰子 / 日志 / 角色
└─────────────────────┘
```

- **遭遇结构**：竖屏时间战役由**房间序列**构成，每间房是一个事件节点（战斗 / 检定 / 对话 / 拾取 / 分支门），完成当前房间→推进条前进→下一间解锁；房间门上的图标预示类型与风险。
- **核心操作**：操作台四 Tab 横滑；动作轮盘收在拇指弧区；关键判定全屏演出。
- **入口 / 出口**：同③。

### ⑤ 事件中心

- **目的**：进行中任务事件（L3 实例）的清单——“世界正在发生什么”。
- **内容构成**：
  - 事件卡列表：名称、来源故事线、目标、剩余时间（时间钟格数，若有）、推荐战力；
  - 触发提示区：新旗标点亮的节点、新解锁分支的“新”标记；
  - 已完结事件自动归档至历史卷轴。
- **核心操作**：查看事件详情；跳转关联战役入口；放弃可选事件（写旗标）。
- **入口**：主屏（有更新时带角标）。
- **出口**：主屏；② 战役入口。

### ⑥ 背包与图鉴

- **目的**：道具查看与收集进度——道具四重身份的展示窗口。
- **内容构成**：
  - 背包页：按身份筛选（数值装备 / 检定工具 / 分支钥匙 / 图鉴信物）；道具详情弹层展示属性、检定修正、已开启的分支提示（“这枚印戒似乎能在某处派上用场”）；
  - 图鉴页：系列收集进度、已解锁 Lore 条目、集齐奖励预告。
- **核心操作**：查看、装备 / 卸下（战役外）、筛选。
- **入口**：主屏；结算界面“查看新获得”。
- **出口**：主屏；角色界面（装备联动）。

### ⑦ 角色

- **目的**：队伍与角色卡——数值、状态、羁绊的总览。
- **内容构成**：队伍横排切换；角色卡（属性、技能、法术位、装备槽、状态效果）；羁绊页（队友好感与相关个人任务线进度）。
- **核心操作**：查看、加点 / 配装（战役外或休整态内）。
- **入口**：主屏；遭遇休整态。
- **出口**：主屏；背包（装备联动）。

### ⑧ 历史卷轴

- **目的**：事件流的档案库——回答玩家心中那句“为什么会变成这样”。
- **内容构成**：
  - 时间轴：全部事件流按时间倒序，可按战役 / 故事线筛选；
  - 每条可展开：检定明细（骰值 + 修正 = 结果 vs 难度）、造成的旗标变化；
  - **旗标追溯**：任一剧情节点可查看“由哪些事件点亮”，形成因果链视图；
  - 战报回放：重要战斗的事件流重演（纯演出，不可改结果）。
- **核心操作**：浏览、筛选、追溯、回放。
- **入口**：主屏；各界面弹层唤起；结算界面“新增条目”。
- **出口**：来源界面。

### ⑨ 结算界面

- **目的**：单局的句点，元循环的落笔处——把状态板的变化“念给玩家听”。
- **内容构成**：经验与等级变化；战利品（新道具高亮，可跳背包）；旗标变化摘要（“铁匠欠你一个人情”）；声望与时间钟推进动画；新解锁内容预告。
- **核心操作**：继续下一遭遇 / 回主屏 / 查看新增卷轴条目。
- **入口**：任一遭遇结束。
- **出口**：下一遭遇（③/④）；① 主屏；⑧ 历史卷轴。

## 5. 界面闭环检查表

| 界面 | 入口（来路） | 出口（退路） | 闭环 |
|---|---|---|---|
| ① 主屏 | 启动、⑨结算、各功能返回 | ②⑤⑥⑦⑧ | ✅ 枢纽 |
| ② 战役入口 | ①、⑤跳转 | ③/④、① | ✅ |
| ③ 横屏遭遇 | ②、上一遭遇 | ⑨、⑤（撤退） | ✅ |
| ④ 竖屏遭遇 | ②、上一遭遇 | ⑨、⑤（撤退） | ✅ |
| ⑤ 事件中心 | ① | ①、② | ✅ |
| ⑥ 背包图鉴 | ①、⑨ | ①、⑦ | ✅ |
| ⑦ 角色 | ①、休整态 | ①、⑥ | ✅ |
| ⑧ 历史卷轴 | ①、各界面弹层、⑨ | 来源界面 | ✅ |
| ⑨ 结算 | ③/④ | ①、③/④、⑧ | ✅ |

规则：任何新增界面（含子游戏界面）进入框架前，必须能通过这张表的“入口 / 出口”双列检查——这是内容包上线 checklist 的一部分（见 `03-TASKS.md` P2）。

## 6. 与子游戏的关系

子游戏复用本框架界面：

- 子游戏入口挂接在 ② 战役入口区（作为特殊战役书卡）或事件中心；
- 子游戏内部界面可自定义，但**进场与离场必须经过 ⑨ 结算界面**（写状态板是硬要求）；
- 子游戏不新增全局导航项，保证九类界面的闭环不被破坏。

## 7. 开放项（随原型阶段细化）

- 视觉风格与字体阅读层级；
- 各界面转场动画时长规范；
- 横屏五区与竖屏三段的精确比例；
- 运营位的内容审核规则。
