# UI/UX 设计文档（框架级）

> 版本：v1.0（定稿，P0.7 评审通过：九类界面规格评审完成，闭环检查表全绿）
> 关联文档：`01-框架白皮书.md`、`02-PRD.md`；掷骰演出分级标准见 `09-遭遇与双模式交互规范.md` §6
> 范围：本文档从框架角度定义全部界面的职责、结构与导航闭环——**每个界面都是世界状态板或事件流的一个视图**。不含视觉稿与像素规范（属原型阶段，另行立项）。

---

## 1. 设计原则

1. **一切界面是状态的视图**：界面不持有数据，只读世界状态板与事件流；界面的出现与消失由状态板变化驱动（与白皮书 §4 铁律一致）。
2. **闭环导航**：任何界面都有明确的来路（入口）与退路（出口），玩家永远不会停在死端。
3. **一个主焦点**：同屏只有一个主内容区，其余信息以边缘常驻或弹层形态存在。
4. **仪式感分级**：掷骰、关键剧情等情绪高点独占屏幕；常规操作轻量快速。
5. **框架先于内容**：本文档定义的界面结构对任何战役、故事线、子游戏内容包通用，内容只填充，不改结构。

## 2. 信息架构与导航闭环

九类界面构成完整游戏闭环：

```
                        ┌──────────────┐
                        │  ① 主屏（营地） │
                        └──────┬───────┘
        ┌──────────┬───────────┼───────────┬──────────┐
        ▼          ▼           ▼           ▼          ▼
   ② 战役入口   ⑤ 事件中心   ⑥ 背包图鉴   ⑦ 角色    ⑧ 历史卷轴
        │
        ▼ （双模式战役在此分支：横屏空间 / 竖屏时间；单模式直接进入）
   ③④ 遭遇（按战役声明形态渲染）
        │
        ▼
   ⑨ 结算界面 ──→ 回 ① 主屏 / 进入下一遭遇 / 查看 ⑧ 新增卷轴条目
```

约定：

- **主屏是唯一枢纽**：所有功能界面从主屏进入，操作结束回到主屏；
- **战役线是主动脉**：主屏 → 战役入口 → 遭遇 → 结算 → 主屏，一圈即一次元循环（对应白皮书 §9）；
- ⑧ 历史卷轴是唯一可从几乎所有界面以弹层形式唤起的界面（随时可查“为什么会这样”）。

## 3. 全局元素（跨界面常驻）

### 3.1 状态栏带

- 位置：各主界面顶部窄条；
- 内容：纪元时间钟（Doom Clock）总览格、队伍 HP 概览、当前战役进度；
- 铁律：**只放“看”的信息，不放“点”的高频操作**（顶部是拇指最难够的区域）；
- 例外交互：点时间钟 → 弹层显示时间边相关的逼近事件预告。

### 3.2 骰子系统

- D20 是全局元素，不属于任何单一界面；
- 演出分级：**普通检定**就地快速结算（≤0.5 秒）；**关键检定**（死亡豁免、剧情拐点、战役模式选择涉及命运判定时）全屏物理演出；
- “哪些判定算关键”由内容包标记，框架只提供两级演出容器。

### 3.3 弹层与抽屉

- 半屏弹层：角色卡、道具详情、时间钟预告——不打断当前界面情境；
- 底部抽屉：日志展开、对话选项——上滑展开、下滑收起；
- 全屏接管：仅限关键检定演出与战役通关演出。

## 4. 界面规格

以下每个界面按统一格式描述：目的 / 内容构成 / 核心操作 / 入口 / 出口。

### ① 主屏（营地）

- **目的**：游戏枢纽，元循环的起点与终点；呈现“世界现在的样子”。
- **内容构成**：
  - 中央：营地 / 世界图景（随纪元进度与旗标视觉变化——状态板的可视化）；
  - 可点亮位：战役入口（含进行中战役的“继续”）、事件中心（有未读触发时带角标）、背包图鉴、角色、历史卷轴；
  - 顶部：全局状态栏带；
  - 运营位：新内容包上架提示（框架级位，内容由投放决定）。
- **核心操作**：进入各功能界面；继续进行中的战役。
- **入口**：启动游戏；结算界面返回；各功能界面返回。
- **出口**：通往 ②⑤⑥⑦⑧。

### ② 战役入口

- **目的**：战役书的“封面”与**模式分支选择点**（框架修正后的核心界面）。
- **内容构成**：
  - 战役书卡：标题、所属纪元、简介、推荐等级、预计时长；
  - **模式分支区**（双模式战役）：两张形态卡并排——「横屏空间战役」（强调战术格、站位、大战场）与「竖屏时间战役」（强调多房间、叙事流、单手节奏），各附差异说明与推荐标签；选择即一次分支，写入状态板；
  - **强制模式**（单模式战役）：不呈现选择，以叙事化包装直接进入（例：“这一段记忆只能以碎片的方式回放”→ 强制竖屏时间）；
  - 多周目信息：已玩模式标记、本战役已探索分支占比（服务收集与重玩）。
- **核心操作**：选模式（若可选）→ 开始；查看分支收集进度。
- **入口**：主屏；事件中心的任务跳转。
- **出口**：进入遭遇（③或④）；返回主屏。

### ③ 遭遇 · 横屏空间形态

- **目的**：把战场摊开——空间感、站位、战术。
- **布局**（横屏五区）：

```
┌──────────────────────────────────────────┐
│ 上缘：队伍状态条 + 先攻顺序条（战斗时展开）   │
│ ┌─────────┬────────────────────┬───────┐ │
│ │ 左栏     │  中央主视野         │ 右栏  │ │
│ │ 行动轮盘 │  战术格地图          │ 骰子盘│ │
│ │         │  （探索/战斗共用镜头）│      │ │
│ └─────────┴────────────────────┴───────┘ │
│ 下缘：日志带（上滑展开半屏）                 │
└──────────────────────────────────────────┘
```

- **核心操作**：左栏选动作 → 中央点目标格 → 确认；右缘掷骰；下缘查日志。
- **入口**：战役入口（横屏形态）；战役中下一遭遇。
- **出口**：结算界面⑨；紧急撤退（若有该边）→ 事件中心。

### ④ 遭遇 · 竖屏时间形态

- **目的**：把故事流过去——多房间逐节拍推进，单手可达，通勤友好。
- **信息策略**：竖屏不靠空间分区，靠**时间分区**——同一批像素在不同瞬间服务不同功能，每一刻都是满屏单一焦点。

#### ④.1 三段式布局与“呼吸”规则

```
┌─────────────────────┐
│ ① 状态栏带（8%）      │ 队伍头像 + HP 环 + 先攻序（战斗时展开）
├─────────────────────┤
│                     │
│ ② 主视野（55~62%）    │ 当前房间 / 遭遇场景 / 对话演出
│                     │
├─────────────────────┤
│ ③ 操作台（30~37%）    │ Tab：行动 / 骰子 / 日志 / 角色
└─────────────────────┘
```

三段高度不是固定的，随遭遇状态机（白皮书 §6）“呼吸”：

| 遭遇状态 | ① 状态栏带 | ② 主视野 | ③ 操作台 | 说明 |
|---|---|---|---|---|
| 探索态 | 8% | 62% | 30% | 视野最大，突出场景氛围 |
| 战斗态 | 12%（展开先攻序） | 55% | 37% | 操作台展开完整动作轮盘 |
| 对话态 | 8% | 50% | 42% | 操作台变为对话选项列表 |
| 关键判定 | 0% | ~90% | 0% | 操作台整体退屏，全屏掷骰演出 |
| 结算过渡 | 8% | 62% | 30% | 落回探索态布局 |

铁律：高度变化必须伴随状态机的状态切换发生，**不允许无剧情理由的界面抖动**。

#### ④.2 房间序列：竖屏战役的骨架

竖屏时间战役由**房间序列**构成，每间房是一个事件节点：

- **推进条**：主视野顶部（状态栏带下方）一条横向房间进度轨，已过的房间点亮、当前房 pulsate、未来房间只显示门图标剪影；
- **房间门预示**：门上的图标组合预告内容与风险——类型图标（战斗 / 检定 / 对话 / 拾取 / 分支门）+ 危险度色阶（来自内容包标注），玩家进门之前就有决策信息；
- **分支门**：一扇门内出现两条路径时，门扉左右裂开成两个选项卡，即故事有向图的“选择边”在竖屏的形态；
- **推进方式**：完成当前房间 → 推进条前进一格 → 下一间解锁，镜头沿竖向纵深感“走入”下一间房（向上推移，强化“深入”的方向感）；
- **回退**：允许走回已过房间（查看遗留拾取），但已完成的检定与战斗不重置。

#### ④.3 五种房间类型的呈现

| 房间类型 | 主视野呈现 | 操作台配合 |
|---|---|---|
| 战斗房 | 竖向战场（见 ④.4） | 行动 Tab 动作轮盘 |
| 检定房 | 场景特写 + 可交互物高亮 | 骰子 Tab 前置，一键快掷 |
| 对话房 | NPC 镜头推近演出 | 操作台变选项列表，带检定角标 |
| 拾取房 | 场景 + 微光提示点 | 日志 Tab 记录获得 |
| 分支门 | 双选项卡裂门演出 | 不参与，主视野内直接选择 |

#### ④.4 竖屏战斗：三个解法组合

竖屏宽度放不下横向大战场，三个机制组合解决：

1. **竖向战场**：战场设计成长条形（走廊、栈道、峡谷），敌在上方、我在下方，天然契合竖构图；
2. **智能镜头**：默认跟随当前行动单位的局部视角（约 5×7 格可视），回合焦点切换时镜头平滑推移；双指捏合随时拉远成全局俯瞰，松手弹回；
3. **斜 45° 伪 3D**：纵深方向压缩，比纯正俯视多挤出 2~3 排有效格子，同时保留单位模型的立体感。

约束：竖屏战役的关卡设计必须遵守**同屏单位上限**（建议 ≤8，具体数值随原型验证），大规模战役在设计期就应声明为横屏空间形态——这是内容包模式声明的依据之一。

#### ④.5 操作台四 Tab 规格

底部手势横滑切换，Tab 指示点常驻但不占行高：

- **行动**：当前单位的动作轮盘（主动作 / 附赠 / 移动 / 物品），按当前情境实时过滤可用项；点选后主视野高亮目标格，二次确认执行；
- **骰子**：D20 常驻托盘。普通检定一键快掷（条形动画 ≤0.5 秒出结果）；关键判定触发全屏物理演出——演出按重要性分级，避免审美疲劳；
- **日志**：本场遭遇的事件流，半屏信息流；点任一条目可唤起该时刻的镜头回放（与历史卷轴同源）；
- **角色**：当前单位角色卡缩略版（HP / 法术位 / 状态 / 装备槽），完整角色卡再上滑全屏。

#### ④.6 手势与热区

| 手势 | 位置 | 作用 |
|---|---|---|
| 点按 | 主视野 | 选中单位 / 目标格 / 可交互物 |
| 长按 | 主视野单位 | 弹出信息卡（半屏弹层） |
| 横滑 | 操作台 | 切换四 Tab |
| 上滑 | 操作台日志 Tab | 展开半屏完整日志 |
| 双指捏合 | 主视野 | 全局俯瞰 ↔ 跟随镜头 |
| 下滑 | 推进条 | 查看已过房间列表，快速回退 |

热区铁律：动作轮盘与确认键收在**下半屏拇指弧区**，大屏机型单手全覆盖；顶部区域（状态栏带、推进条）只承担低频操作。

#### ④.7 房间转场与演出分级

- 房间间转场：推进条前移 + 镜头纵深推移，时长预期 ≤1 秒，不打断节奏；
- 全屏接管仅限：关键判定演出、Boss 登场、房间序列终点的剧情演出；
- 一切演出可跳过（长按），跳过不丢信息——演出内容同步写入日志 Tab 与历史卷轴。

- **入口 / 出口**：同③。

### ⑤ 事件中心

- **目的**：进行中任务事件（L3 实例）的清单——“世界正在发生什么”。
- **内容构成**：
  - 事件卡列表：名称、来源故事线、目标、剩余时间（时间钟格数，若有）、推荐战力；
  - 触发提示区：新旗标点亮的节点、新解锁分支的“新”标记；
  - 已完结事件自动归档至历史卷轴。
- **核心操作**：查看事件详情；跳转关联战役入口；放弃可选事件（写旗标）。
- **入口**：主屏（有更新时带角标）。
- **出口**：主屏；② 战役入口。

### ⑥ 背包与图鉴

- **目的**：道具查看与收集进度——道具四重身份的展示窗口。
- **内容构成**：
  - 背包页：按身份筛选（数值装备 / 检定工具 / 分支钥匙 / 图鉴信物）；道具详情弹层展示属性、检定修正、已开启的分支提示（“这枚印戒似乎能在某处派上用场”）；
  - 图鉴页：系列收集进度、已解锁 Lore 条目、集齐奖励预告。
- **核心操作**：查看、装备 / 卸下（战役外）、筛选。
- **入口**：主屏；结算界面“查看新获得”。
- **出口**：主屏；角色界面（装备联动）。

### ⑦ 角色

- **目的**：队伍与角色卡——数值、状态、羁绊的总览。
- **内容构成**：队伍横排切换；角色卡（属性、技能、法术位、装备槽、状态效果）；羁绊页（队友好感与相关个人任务线进度）。
- **核心操作**：查看、加点 / 配装（战役外或休整态内）。
- **入口**：主屏；遭遇休整态。
- **出口**：主屏；背包（装备联动）。

### ⑧ 历史卷轴

- **目的**：事件流的档案库——回答玩家心中那句“为什么会变成这样”。
- **内容构成**：
  - 时间轴：全部事件流按时间倒序，可按战役 / 故事线筛选；
  - 每条可展开：检定明细（骰值 + 修正 = 结果 vs 难度）、造成的旗标变化；
  - **旗标追溯**：任一剧情节点可查看“由哪些事件点亮”，形成因果链视图；
  - 战报回放：重要战斗的事件流重演（纯演出，不可改结果）。
- **核心操作**：浏览、筛选、追溯、回放。
- **入口**：主屏；各界面弹层唤起；结算界面“新增条目”。
- **出口**：来源界面。

### ⑨ 结算界面

- **目的**：单局的句点，元循环的落笔处——把状态板的变化“念给玩家听”。
- **内容构成**：经验与等级变化；战利品（新道具高亮，可跳背包）；旗标变化摘要（“铁匠欠你一个人情”）；声望与时间钟推进动画；新解锁内容预告。
- **核心操作**：继续下一遭遇 / 回主屏 / 查看新增卷轴条目。
- **入口**：任一遭遇结束。
- **出口**：下一遭遇（③/④）；① 主屏；⑧ 历史卷轴。

## 5. 界面闭环检查表

| 界面 | 入口（来路） | 出口（退路） | 闭环 |
|---|---|---|---|
| ① 主屏 | 启动、⑨结算、各功能返回 | ②⑤⑥⑦⑧ | ✅ 枢纽 |
| ② 战役入口 | ①、⑤跳转 | ③/④、① | ✅ |
| ③ 横屏遭遇 | ②、上一遭遇 | ⑨、⑤（撤退） | ✅ |
| ④ 竖屏遭遇 | ②、上一遭遇 | ⑨、⑤（撤退） | ✅ |
| ⑤ 事件中心 | ① | ①、② | ✅ |
| ⑥ 背包图鉴 | ①、⑨ | ①、⑦ | ✅ |
| ⑦ 角色 | ①、休整态 | ①、⑥ | ✅ |
| ⑧ 历史卷轴 | ①、各界面弹层、⑨ | 来源界面 | ✅ |
| ⑨ 结算 | ③/④ | ①、③/④、⑧ | ✅ |

规则：任何新增界面（含子游戏界面）进入框架前，必须能通过这张表的“入口 / 出口”双列检查——这是内容包上线 checklist 的一部分（见 `03-TASKS.md` P2）。

## 6. 与子游戏的关系

子游戏复用本框架界面：

- 子游戏入口挂接在 ② 战役入口区（作为特殊战役书卡）或事件中心；
- 子游戏内部界面可自定义，但**进场与离场必须经过 ⑨ 结算界面**（写状态板是硬要求）；
- 子游戏不新增全局导航项，保证九类界面的闭环不被破坏。

## 7. 开放项（随原型阶段细化）

- 视觉风格与字体阅读层级；
- 各界面转场动画时长规范；
- 横屏五区与竖屏三段的精确比例；
- 运营位的内容审核规则。
