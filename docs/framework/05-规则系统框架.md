# 规则系统框架（规则包 / Rule Pack）

> 版本：v1.0（定稿，P0.8 评审通过）
> 关联文档：`01-框架白皮书.md` §11、`02-PRD.md` F7；首个轻规则包细则见 `11-轻规则包-v1.md`
> 范围：定义规则深度作为框架扩展轴的抽象模型。具体数值策划见 `11-轻规则包-v1.md`。

---

## 1. 定位

规则深度不是一次拍板的产品决策，而是框架的**扩展轴**：

- 框架只恒定 D20 最小核，其余规则由**规则包**承载；
- 规则包是内容包的一种，可独立发布、独立版本化；
- 不同战役 / 子游戏可绑定不同深度的规则包，在同一框架下共存；
- **首个主线采用轻规则包启动**（方向已定），后续内容包可引入更深规则，框架无需改动。

## 2. D20 最小核（所有规则包共享）

以下三条是框架的不可变部分，任何规则包不得绕过：

1. **D20 检定**：骰值 + 修正 vs 难度，输出成功 / 失败双分支——对应白皮书 §5 的检定边；
2. **事件流输出**：一切规则结算的结果以事件流输出，渲染层、历史卷轴、成就系统只消费事件流；
3. **状态板读写**：规则包只能通过读写状态板变量影响剧情分支，不得直接触碰剧情节点。

## 3. 规则包六要素

一个规则包必须完整定义以下六个要素，缺一不可：

| 要素 | 内容 | 轻规则示例（方向性） |
|---|---|---|
| 属性模型 | 角色有哪些数值维度 | 3 维（力 / 敏 / 智）+ HP |
| 检定公式 | 修正如何计算、难度如何标定 | 修正 = 属性值，难度三档（易/中/难） |
| 行动经济 | 每回合可做什么 | 移动 + 动作 + 附赠，三段式 |
| 战斗回合结构 | 先攻、回合循环、胜负条件 | 先攻 = 敏检定，回合轮转 |
| 成长曲线 | 升级获得什么 | 每级 +HP、解锁 1 技能槽 |
| 死亡与失败 | 归零后的处理 | 死亡豁免三局两胜，队友可救 |

## 4. 规则深度三档预设

| 档位 | 面向 | 属性模型 | 行动经济 | 特色系统 |
|---|---|---|---|---|
| 轻规则 | 首发主线、碎片时间玩家 | 3 维 + HP | 三段式 | 无法术位，技能次数制 |
| 标准 | 核心 RPG 玩家 | 6 维 + HP + 熟练项 | 三段式 + 反应动作 | 状态效果体系、技能树 |
| 深度 | 跑团爱好者 | 类 5e 全属性 | 完整动作经济 | 法术位、豁免、专长、优势/劣势 |

- 三档是**预设模板**，内容包可基于模板微调（如“轻规则 + 法术位”的混合档）；
- 档位之间不要求向上兼容——战役声明绑定某档位即按该档位运行；
- 新档位 = 新规则包模板，走内容包管线评审。

## 5. 绑定模型

- **战役级绑定**：每本战役书声明所需规则包 ID 与最低版本；进入战役时按声明加载；
- **子游戏**：可自带规则包（变体规则），也走六要素完整性校验；
- **共存**：同一存档中，不同战役可各跑各的规则包——状态板变量类型是公共语言，规则包只是不同的“读写方言”；
- **队伍数据桥接**：角色跨战役携带时，由规则包声明的属性映射表负责转换（如深度档 6 维属性折叠为轻规则 3 维的映射规则），映射表随规则包发布。

## 6. 与其他框架层的关系

| 框架层 | 关系 |
|---|---|
| 世界状态板 | 规则包读写状态板，变量类型恒定，不随规则深度变化 |
| 事件流 | 不同规则包产生的事件流格式一致，只是数值来源不同 |
| 双形态渲染 | **渲染层对规则档位无感**——同一渲染器服务所有规则包 |
| 界面闭环 | 角色界面（⑦）的字段集随当前战役的规则包动态呈现 |
| 历史卷轴 | 检定明细展示“规则包名 + 公式”，保证可追溯 |

## 7. 版本与迭代

- 规则包独立版本号，与框架版本、内容包版本三方解耦；
- 规则包升级时：**进行中战役可冻结在旧版本下完成**，新开局默认使用新版本；
- 玩家可在战役入口看到本战役使用的规则包版本标识；
- 规则包废弃（EOL）时，存量进行中战役必须能跑完——冻结机制是硬保证。
