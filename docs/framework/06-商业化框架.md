# 商业化框架（权利模型 / Entitlement）

> 版本：v1.1（定稿，P0.9 评审通过；v1.1 补充策略包级可选与运营迭代轨）
> 关联文档：`01-框架白皮书.md` §10.4/§12、`02-PRD.md` F8、`04-UI-UX设计文档.md`、`../tech/02-内容包格式规范.md` §2.2/§2.3
> 范围：定义付费模式作为框架扩展轴的抽象模型。具体定价、首发付费策略为运营决策，另行立项（上架前拍板，见 `03-TASKS.md` P0.5）。

---

## 1. 定位

付费模式不是框架形态，而是**投放策略**：

- 框架提供统一的**权利模型**，四种主流付费模式全部支持、可混合、可逐版本调整；未来新增付费模式只要落在"点亮权利变量"上即自动获得支持；
- **付费策略是包级选择**：每个战役 / 子游戏独立声明参与哪些付费策略（§3.2），配合运营决策逐版本调整；
- 商业化与规则、剧情一样遵守框架铁律：只通过状态板生效；
- 首发采用哪种付费策略，不阻塞框架冻结（M0），在上架前拍板即可。

## 2. 权利模型（Entitlement）

### 2.1 权利是什么

- **权利 = 状态板上的全局变量**（归框架层命名空间管理，见白皮书 §4.3）；
- 内容包声明自己的解锁条件（需要哪些权利变量为真）；
- **点亮权利的手段是多样的**：购买、活动赠送、成就奖励、多周目继承——付费只是其中之一。这一设计让“免费试玩章节”“成就解锁隐藏战役”等运营手段与付费复用同一机制。

### 2.2 权利的粒度

| 粒度 | 示例 |
|---|---|
| 本体权利 | 基础游戏资格 |
| 战役权利 | 某本战役书 / 某个故事分支包 |
| 权益权利 | 订阅期内的提前解锁权、专属外观使用权 |
| 外观权利 | 骰子皮肤、角色外观、演出特效 |

### 2.3 权利变量规范

- 命名空间：统一挂在 `global.entitlement.*` 下（如 `global.entitlement.campaign01`），归框架层管理（`07-世界状态机规范.md` §3）；
- **写权限仅商店 / 活动 / 成就系统**，内容包只读；写入即生效，无需重启；
- **注册表**：全部合法权利变量登记在运营侧注册表 `packs/_ops/entitlements.json`（数据文件，非代码常量）——新增权利 = 运营侧登记一行；校验器 V9 以此表核对内容包引用的权利变量已注册；
- 内容包解锁条件声明格式：manifest `entitlement.requires`（数据契约见 `../tech/02-内容包格式规范.md` §2.2）；
- 权利变更同样携带溯源进事件流（购买单号 / 活动 ID），支持退款回收的精确回退。

## 3. 四种付费模式的框架支持

| 模式 | 挂载点 | 玩家侧呈现 |
|---|---|---|
| 买断本体 | 基础权利包 | 应用商店一次性购买 |
| 内容包 DLC | 战役 / 故事线包声明权利门槛 | 战役入口（②）的战役书卡呈现“锁定态” |
| 订阅 | 周期性权利集合 | 主屏运营位 + 事件中心的订阅权益区 |
| 外观 / 演出商品 | 只写外观旗标 | 背包图鉴（⑥）的外观页、骰子皮肤槽 |

### 3.1 锁定态呈现规范

- 未解锁的付费战役在战役入口**可见但锁定**——呈现封面、简介、分支收集度，而不是隐藏：让内容本身成为最好的销售页；
- 锁定态包装叙事化（与强制模式同一手法），不出现生硬的“未购买”弹窗打断浏览；
- 购买后权利即时写入状态板，入口当场解锁，无需重启。

### 3.2 策略选择与调整（包级 + 运营侧）

**职责切分（消歧关键）**：

| 侧 | 决定什么 | 载体 | 稳定性 |
|---|---|---|---|
| 内容包 | **门槛**：解锁本包需要哪些权利 | manifest `entitlement.requires`（硬门槛）+ `monetization.strategies`（策略参与声明，见 `../tech/02-内容包格式规范.md` §2.3） | 稳定：随内容包版本走 |
| 运营 | **点亮**：权利怎么发——定价、购买、订阅集合、活动赠送、成就奖励、限时免费 | 权利变量写入方（商店 / 活动 / 成就系统） | 可变：随时调整，不发内容包新版 |

- 一个包可同时参与多种策略：例 `战役 X` 声明 `requires: [entitlement.campaign_x]` 后，运营既可直接售卖（DLC），也可把 `campaign_x` 权利纳入订阅集合（订阅），还可限时免费点亮（活动）——**内容包对此完全无感**；
- **已获权利不降级原则**：策略收紧（如免费转付费）只影响未解锁玩家；任何调整不得回收玩家已合法获得的权利（退款流程除外，§5）；放宽（如 DLC 转订阅包含）即时生效；
- 策略调整走运营评审，不进内容包管线——这是运营轨迭代（白皮书 §10.4）与内容轨迭代的边界；
- **限免回收机制**：限时点亮（活动 ttl）由**运营侧定时任务**负责到期置假，框架只保证"权利置假 → 入口即锁、进行中战役可跑完"（§5 同一哲学）；游戏运行时不内置倒计时逻辑。

## 4. 付费禁区（铁律）

1. **付费点不挂在检定结果上**——骰子的公正性不可售卖，任何“付费重掷”“付费加修正”永久禁止；
2. **付费内容不破坏免费路径的分支完整性**——免费玩家的战役必须是完整故事，付费包是加法不是解锁结局；
3. **数值强度不卖**（若未来引入外观以外商品，须重新评审本条）；
4. 付费内容包走与免费内容包**完全相同的**分支校验、命名空间检查与界面闭环检查。

## 5. 与内容包管线的关系

- 付费内容包 = 普通内容包 + 权利门槛声明，管线、校验、版本规范完全复用（白皮书 §10）；
- 权利变量的写入方（商店 / 活动 / 成就系统）对内容包透明——内容包只读权利状态；
- 退款 / 权利回收：权利变量置假后，进行中战役的处理策略为**允许跑完当前战役，不可开新局**（与规则包冻结机制同一哲学）。

## 6. 与界面闭环的关系

- 商业化不新增全局导航项：商店能力挂在 ① 主屏运营位、② 战役入口锁定态、⑥ 背包外观页三处既有界面内；
- **主屏运营位内容由运营配置投放**：`packs/_ops/ops_config.json` 的 `home_promo` 块（文案 + 目标跳转 pack_id/codex）；配置为空则运营位整体隐藏，不出空位；
- 购买流程以半屏弹层完成，不离开当前界面情境（遵守 04 文档 §3.3 弹层规范）；
- ⑨ 结算界面不做任何付费引导——情绪高点的句点保持纯粹。

## 7. 首发付费策略（已拍板，2026-11-09）

**本体免费 + 内容包 DLC + 外观/演出商品**：

- 理由：本作的核心卖点是"世界在生长"（内容包持续投放），本体免费最大化首触达，DLC 与内容管线天然同构；买断不利于持续投放模型，订阅在内容量不足时不启用；
- 订阅模式**本期不启用**（订阅权益区同步不做）；当内容包存量达到订阅门槛（≥5 个战役包）时重新评审；
- 落地映射：campaign01 = 本体免费；arena = DLC（已上线演示全链路）；外观商品位 = 骰子皮肤（图鉴「命骰考」集齐奖励，纯演出）；
- 外观商品位落地细化（2026-11-09 实装）：皮肤注册表 = 运营侧数据文件 `packs/_ops/cosmetics.json`（与 §2.3 权利注册表同构——"点亮在运营"：定价、获得途径映射、默认皮肤指定均在运营侧登记，内容包管线零改动）；写板键 = `global.cosmetic.*`（07 文档 §3 v1.2 白名单，仅 system 可写）；获得路径 = 命骰考集齐（10 文档 §4）+ 商店外观商品（首发占位「拾遗铜辉」¥6），购买入口 = ⑥ 背包外观页半屏弹层（§6 三处既有界面内，不新增全局导航）；
- 禁区复核（§4 四条）：本策略下全部满足——免费路径完整、不卖数值、不碰骰子、付费包同校验。

## 8. 细化项（运营立项时）

定价体系与地区差异化、平台分成与合规（未成年人保护、概率公示等）在定价立项时细化；订阅权益清单在订阅启用评审时细化。
