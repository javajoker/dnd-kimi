> 关联文档：`01-框架白皮书.md` §4、`../tech/01-技术方案讨论稿.md` §4、`../tech/02-内容包格式规范.md` §4.6
> 范围：世界状态板六类变量的完整字段定义、命名空间规则、存档快照规则、时间钟行为规范。框架与全部内容包共同遵守。

## 1. 状态板总结构

状态板是单一可变 store：`Map<NamespacedKey, TypedValue>`。六类变量是同一套键值之上的六个**语义标签**，存储、读写、快照路径统一，标签供 UI 分组与校验器检查。

每次写入必须携带溯源：`provenance = { event_id, node_id, pack_id }`（历史卷轴"旗标追溯"的数据来源，04 文档界面⑧）。

## 2. 六类变量字段定义

| 变量 | 键格式 | 类型 | 取值范围 | 默认值 | 主要写入方 | 主要读取方 |
|---|---|---|---|---|---|---|
| 剧情旗标 Flag | `<ns>.<flag_id>` | bool | true/false | false | 节点 `on_enter`/边 `effects`/事件结算 | 边条件、演出差异、历史卷轴 |
| 声望 Reputation | `global.rep.<faction>` | int | **-5 ~ +5** | 0 | 节点/边效果、事件结算 | 声望边、商店、NPC 态度 |
| 时间钟 Doom Clock | `global.doom_clock`（纪元钟）/ `<ns>.clock.<id>`（局部钟） | int | **0 ~ 10** | 0 | 边效果 `clock`、事件结算 | 时间边、结局兜底、状态栏带 |
| 物品持有 Inventory | `global.inv` | Set<item_id> | 道具表已注册 ID | {} | `give_item` / `remove_item` 效果 | 道具边、背包图鉴、结局条件 |
| 羁绊 Bond | `global.bond.<npc_id>` | int | **0 ~ 100** | 0 | 对话选项、事件结算 | 结局条件、个人任务线、离队事件 |
| 抉择倾向 Alignment | `global.alignment` | int | **0 ~ 100**（0=全留白，100=全墨守） | **50**（中线） | 关键选择边 | 结局分型（`ink_gt 50` / `blank_gt 50`） |

约束：

- 数值越界钳位（clamp）在写入时发生，并产出 `clamped` 事件进事件流（不静默）；
- `global.inv` 的元素必须是已加载内容包 items.json 注册过的 ID——校验器 V7 与运行时双重检查；
- 计数型旗标（如残简收集度）不落 Flag，以 `item.<id>` 数量查询表达（见 `02-内容包格式规范.md` §4.6）；
- **`global.lore`**：图鉴条目解锁集合（Set<lore_id>），效果词汇 `lore` 写入（10 文档 §3）；`global.tutorial.*`：教程触发记录（12 文档 §4）。

## 3. 命名空间规则

| 前缀 | 归属 | 写权限 | 读权限 |
|---|---|---|---|
| `global.rep.*` / `global.alignment` / `global.bond.*` / `global.inv` / `global.doom_clock` / `global.lore` / `global.tutorial.*` / `global.mode_choice.*` | 框架层（全局变量白名单） | 任何内容包（经效果词汇表）；`global.mode_choice.<campaign_id>` 为战役入口模式选择写板键（09 文档 §3） | 任何内容包 |
| `global.entitlement.*` | 框架层（权利变量） | **仅商店 / 活动 / 成就系统**（06 文档 §5） | 内容包只读 |
| `<pack_id>.*` | 内容包私有 | **仅该包** | 任何包（全键引用） |

铁律：

1. 包内声明的旗标自动以本包 ID 为前缀（`campaign01.seen_fading`），内容作者不写前缀；
2. 跨包**写**禁止；跨包**读**允许但必须在 flags.json 的 `readers` 中声明目标包，保证依赖可追溯；
3. 全局变量的语义由本规范定义，内容包不得重定义（如不得把 `rep.scriptorium` 当计数器用）。

## 4. 存档快照规则

### 4.1 快照内容

```
Save = {
  save_version,            // 快照格式版本（整数递增）
  board,                   // 状态板全量
  event_tail,              // 事件流尾部序号（回放与追溯的锚点）
  bindings,                // 各内容包 / 规则包绑定版本表
  rng_seed,                // 种子化 RNG 状态
  meta                     // 周目数、创建/保存时间、战役进度摘要
}
```

### 4.2 快照时机

| 时机 | 说明 |
|---|---|
| 遭遇结算态完成 | 主快照点：一次元循环落笔即存 |
| 主屏闲置 | 兜底快照，防进程被杀丢进度 |
| 手动 | 主屏显式"记录抄本"入口 |

遭遇**进行中不存档**（单局内退出 = 重打该局），与"失败不读档"哲学一致：存档点是世界状态的句读，不是悔棋工具。

### 4.3 兼容策略

- 快照带 `save_version`，加载时按迁移链逐级升级；框架保持对 **最近 2 个大版本** 快照的迁移器；
- 进行中战役的内容包 / 规则包按 `bindings` 冻结在绑定版本下跑完（05 文档 §7），新版本只对新开局生效；
- 多周目继承 = 新快照初始化时按内容包声明的继承清单从旧快照选择性拷贝（拷贝项本身也是数据）。

## 5. 时间钟（Doom Clock）行为规范

1. **区间恒定 0~10**：纪元钟（褪墨度）与局部钟同构；越界钳位；
2. **时间边触发**：钟写入后立即触发一次触发器扫描，满足 `at`/`>=` 条件的 `once` 边触发（见 `../tech/01-技术方案讨论稿.md` §7）；
3. **双向性**：内容设计必须同时存在加速（+）与延缓（-）手段（校验器 V5 检查可收束性）；纯倒计时不允许；
4. **满格语义**：纪元钟满格 = 兜底坏结局触发（如 E4），内容包必须声明满格出口；
5. **呈现**：状态栏带常驻总览格；点按弹出逼近的时间边预告（04 文档 §3.1）——玩家可感知但不可精确倒推，保持张力。

## 6. 与事件流的关系

- 状态板是"现在"，事件流是"怎么来的"：状态板的每一次变化都对应至少一条事件（`flag.written` / `clock.tick` / `rep.changed`……）；
- 反向不成立：事件流中大量事件（伤害、检定明细）不改动状态板；
- 历史卷轴界面⑧ = 事件流视图 + 经溯源键回链状态板。
