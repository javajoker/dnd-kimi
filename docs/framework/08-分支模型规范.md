# 分支模型规范

> 版本：v1.0（定稿，对应 P0.3）
> 关联文档：`01-框架白皮书.md` §5、`../tech/02-内容包格式规范.md` §4（数据层 DSL）、§12（自动化校验）
> 范围：五种边的完整定义与校验规则、"失败即分支"写作规范、节点收束策略与分支预算。数据表达以 `02-内容包格式规范.md` 为准，本文定义设计层语义与约束。

## 1. 五种边的完整定义

| 边类型 | 语义 | 玩家可见性 | 校验硬规则 |
|---|---|---|---|
| 选择边 choice | 玩家明示抉择 | 显式选项卡 | `label` 必填且 ≤20 字；效果入 `effects` |
| 检定边 check | D20 判定，成功/失败双路 | 显式（骰子演出分级，见 09 文档 §6） | **`failure` 必填**；技能名须在绑定规则包注册 |
| 道具边 item | 持有指定物品才显形 | 隐形（持有后显形） | 引用道具须 `roles` 含 `branch_key`；`fallback` 与省略二选一明确 |
| 时间边 doom_clock | 时间钟到格自动触发 | 半可见（时钟预告弹层） | `once: true` 默认；不得指向死路 |
| 声望/倾向边 reputation | 隐形门槛，事后可察觉 | 隐形 | 条件只读全局变量白名单；须在历史卷轴可溯源 |

通用规则：任何边可叠加 `requires` 附加门槛；边的效果（写旗标/时钟/声望）属于"走这条路"而非"到这个点"，禁止把效果写在目标节点冒充边效果。

## 2. "失败即分支"写作规范

每条检定边的失败路必须满足以下**三者之一**：

| 型式 | 内容量要求 | 示例（campaign01） |
|---|---|---|
| A. 独立路径 | ≥1 场遭遇或 1 段独占演出，再汇入主线 | N1-2 失败 → N1-2b 封锁巷战斗 |
| B. 代价汇合 | 与成功路汇于同节点，但失败边携带差异化效果（时钟/声望/旗标/资源） | N2S-1 失败 → 罚时 1 格 |
| C. 惩罚升格 | 失败触发更高难度遭遇，事后强制回到择路点 | N2L-1 失败 → 通缉战 → 强制择链 |

**禁止**：空转汇合（失败 = 无事发生直接汇合）、失败锁死（失败路无出边）、失败即删内容（失败路短到玩家察觉不到分支存在）。

失败路同样需要叙事尊严：失败文本不得是"你失败了"式的系统腔，须是对世界的一次真实改写（世界观：织卷写下了另一个版本）。

## 3. 节点收束策略

1. **支线链 ≤3 节点必收束**：支线（如幕二三方链）从分岔到汇入收束点不超过 3 个节点；
2. **收束携带旗标**：汇流时各路的旗标/声望/时钟状态不同，收束点之后的节点必须以差异化待遇回应（开场白、态度、难度、可用选项），否则视为假收束（校验器以旗标读取检查辅助判定）；
3. **收束点职责单一**：收束点只拼合情报与推进主线，不再引入新分支维度；
4. **独狼/隐藏捷径**：每条隐藏路径须有 ≥2 个可达入口（如声望门槛 + 难度检定），保证"可发现性"不依赖单一周目运气。

## 4. 分支预算（单战役）

| 项 | 预算 | 依据 |
|---|---|---|
| 逻辑节点总数 | 25 ~ 40 | campaign01 实测 31/35；超出即拆分战役 |
| 边总数 | ≤ 2.5 × 节点数 | 防边爆炸稀释分支意义 |
| 单幕节点 | 5 ~ 15 | 白皮书 L2 定义 |
| 单节点出边 | ≤ 5（显式选择 ≤4 + 隐藏边 ≤1） | 竖屏选项列表一屏可读 |
| 检定边占比 | 20% ~ 40% | 保证 D20 仪式感密度又不致骰子疲劳 |
| 结局分型 | 3 ~ 5（含 1 个 `default` 兜底） | 收束性 vs 重玩价值的平衡点 |

预算是**校验器强制项**（V6 及扩展），超预算的包须拆分为多个内容包，不允许例外放行。

## 5. 分支图校验清单

人工设计自检（战役书 §10 模式）+ 自动化校验（`../tech/02-内容包格式规范.md` §12，V1~V10）双层：

| 层 | 检查项 |
|---|---|
| 设计自检 | 每条检定边失败路型式（A/B/C）标注；收束旗标差异化核对；结局条件互斥与兜底 |
| 自动化 | 无死路 / 无不可达 / 失败路完备 / 旗标闭环 / 时钟有界 / 预算 / 命名空间 / 竖屏约束 / 权利声明 / 界面闭环 |

两层结论冲突时以自动化为准并回改设计稿（转写纪律见 `../tech/03-内容包制作操作指南.md` §1）。
