# 遭遇与双模式交互规范

> 版本：v1.0（定稿，对应 P0.4）
> 关联文档：`01-框架白皮书.md` §6/§7、`04-UI-UX设计文档.md` §3/§4、`../tech/02-内容包格式规范.md` §2.1/§6
> 范围：遭遇状态机六态的进入/退出条件、战役模式声明规范、战役入口模式分支规范、横竖屏布局冻结指标、掷骰演出分级标准。

---

## 1. 遭遇状态机：六态进入/退出条件

| 状态 | 进入条件 | 退出条件 | 备注 |
|---|---|---|---|
| 进场 | 节点关联遭遇加载完成（战斗遭遇先经整备阶段，见 §9.1） | 开场事件流投递完毕 → 探索态 | 演出可跳过，内容同步写日志 |
| 探索态 | 默认态 | 可交互物进入交互范围 → 发现态；敌意触发 → 战斗态；NPC 发起 → 对话态 | 与发现态双向流转 |
| 发现态 | 检定 / 拾取 / 陷阱触发点激活 | 结算完该发现 → 回探索态；陷阱/伏击 → 战斗态 | 检定走规则包 |
| 战斗态 | 敌意触发 | 一方全灭 / 撤退边 / 目标达成 → 结算态 | 先攻→回合循环，规则包定义 |
| 对话态 | 对话节点 / NPC 发起 | 选项耗尽 / 检定分支落定 → 探索态或结算态 | 选项可带检定角标 |
| 结算态 | 战斗/对话/探索目标完成 | 写板完成 → 休整态（若有）或出场 | **写状态板是硬要求** |
| 休整态 | 节点声明休整 | 玩家确认离开 → 出场 | 补给、加点、角色界面入口 |

约定：状态切换以 `state.entered` 事件外发，渲染壳（含竖屏三段"呼吸"）只订阅、不被指挥。

## 2. 战役模式声明规范

- 声明位置：manifest `presentation` 字段（格式见 `../tech/02-内容包格式规范.md` §2.1）；
- `mode`：`space` / `time` / `choice`；`forced` 按幕强制；`recommend` 节点级建议；
- **声明依据**（内容作者决策树）：
  - 同屏单位 >8 或大战场 → 必须 `space`（竖屏可读性约束，04 文档 §④.4）；
  - 叙事为残篇/追忆/受限视角 → 应 `time`（世界观 §8 叙事挂钩）；
  - 两者皆可 → `choice`，把模式选择作为一次分支交还玩家；
- 声明后由校验器 V8 复核竖屏遭遇单位数。

## 3. 战役入口模式分支规范

- 双模式战役：入口呈现两张形态卡，各附差异说明（战术格/大战场 vs 多房间/单手节奏）与推荐标签；选择写入 `global.mode_choice.<campaign_id>`，**整场战役锁定**；
- 强制模式：不呈现选择，以叙事化包装进入（如"这一段记忆只能以碎片的方式回放"）；包装文案禁止系统腔（不出现"模式已锁定"等字样）；
- 模式卡同时呈现：已玩模式标记、分支收集占比（多周目重玩引导，04 文档界面②）。

## 4. 横屏空间战役布局规范（冻结指标）

| 区 | 占比 | 职责 |
|---|---|---|
| 上缘 | 8% | 队伍状态条 + 先攻顺序条（战斗时展开） |
| 左栏 | 15% | 行动轮盘（主动作/附赠/移动/物品） |
| 中央 | 60% | 战术格地图，探索/战斗共用镜头 |
| 右栏 | 12% | 骰子盘；关键判定让位全屏演出 |
| 下缘 | 5%（展开至半屏） | 日志带，上滑展开 |

战术格可读性：格边长 ≥ 屏高 8%；同屏格数 ≤ 12×8；弹道线/威胁范围以描边而非色块表达（色弱可读）。

## 5. 竖屏时间战役布局规范（冻结指标）

- 三段式呼吸布局沿用 04 文档 §④.1 比例表（探索 8/62/30，战斗 12/55/37，对话 8/50/42，关键判定全屏接管），本文予以冻结；
- 房间推进节拍：转场 ≤1 秒；推进条位于状态栏带下方；未来房间只显门图标剪影；
- 门预示规范：类型图标（战斗/检定/对话/拾取/分支门）+ 危险度色阶（三档，与轻规则难度表一致）；分支门裂为左右双选项卡；
- 操作台四 Tab（行动/骰子/日志/角色）职责按 04 文档 §④.5 冻结；热区铁律：高频操作收在下半屏拇指弧区。

## 6. 掷骰演出分级标准

| 级别 | 判定范围 | 演出 |
|---|---|---|
| 普通 | 一切未标记为关键的检定 | 就地快掷，条形动画 ≤0.5 秒出结果 |
| 关键 | ① 死亡豁免；② 结局抉择相关检定；③ `difficulty: hard` 且标记剧情拐点的检定；④ 内容包显式标记 `key: true` | 全屏物理演出；长按可跳过，结果同步写日志 |

- 分级由**内容包标记 + 框架固定类别**共同决定：①②是框架恒定关键类，③④由内容作者标注；
- 防审美疲劳红线：单场遭遇关键演出 ≤3 次（校验器对内容包静态估算报警）；
- 自然 20 / 自然 1 无论级别都追加一档特效反馈（命运的极端时刻，世界观 §4.4）。

## 7. 单局退出与中断规范

遭遇内常驻 ☰ 菜单（竖屏：房间推进条右端；横屏：上缘右端），选项：

| 选项 | 行为 |
|---|---|
| 继续 | 关闭菜单 |
| 撤退（条件出现） | 仅内容包声明了撤退边时显示；走"失败即分支"（白皮书 §5.2），写入对应旗标 |
| 保存并回主屏 | **遭遇进行中不存档**（`07-世界状态机规范.md` §4.2）：回到本遭遇进入前的快照，下次进入该遭遇从头开始；弹确认，文案明说进度影响 |
| 手势帮助 | 打开帮助页手势图鉴（`12-手势与交互规范.md` §4） |

- 来电/切后台：系统级中断自动暂停，回来自动续局（内存态保留）；进程被杀按"保存并回主屏"同等处理——玩家**最多损失当前这一局**，绝不影响已写板的世界状态；
- 结算态之后为正常离场（⑨ 结算界面），不经 ☰。

## 8. 双形态差异与切换边界（重申并细化）

- **形态是战役级属性，单局内不可切换**（F1.4）：进入遭遇即按战役声明形态渲染，一局之内不存在横竖屏切换入口；原型中的"形态对比"按钮仅为评审调试，正式版不出现；
- 差异是**结构与节奏**的差异，不只是构图：空间形态=自由站位的战术格沙盘；时间形态=逐房推进的序列（房间门预示、分支门、回退条）——同一事件流，两种"玩法的身体"；
- 内容包按 §2 决策树声明，竖屏遭遇遵守同屏单位 ≤8。

## 9. 整备阶段与快捷栏

### 9.1 整备（Loadout）

- 战斗遭遇在进场前进入**整备界面**：技能备选、道具携带、未分配属性点三块，确认后进入进场态——这是"准备战斗"的仪式化落点；
- **限制与否由游戏配置文件决定**（manifest `loadout` 字段，`../tech/02-内容包格式规范.md` §2.4）：是否启用、道具槽数、技能槽数、是否允许重洗属性点；战役级声明，遭遇级可覆盖；未声明 = 不启用，直接进场；
- 整备选择写入事件流（`loadout.confirm`），历史卷轴可追溯"这局带了什么"。

### 9.2 快捷栏（Tray）

- 单局内的可用技能与可用道具以**快捷栏芯片**呈现（内容 = 当前整备选择 + 情境实时过滤），替代堆叠的选项按钮——避免选项组合爆炸；
- 使用方式（双通道，12 §1 铁律）：**拖动芯片到目标单位/格** = 指定目标使用；**点按芯片** = 默认目标使用；
- 芯片实时呈现次数余量与禁用态（附赠已用 / 次数已尽 / 目标不合法）。
