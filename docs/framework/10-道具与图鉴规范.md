## 1. 道具四重身份标签体系

每件道具携带 `roles` 标签数组（数据格式见 `../tech/02-内容包格式规范.md` §7）：

| 标签 | 身份 | 设计职责 | 硬规则 |
|---|---|---|---|
| `stat` | 数值 | 影响单局强度（武器/护甲/消耗品/强化石） | 数值表随绑定规则包评审 |
| `check_mod` | 检定修正 | 影响检定边通过率 | 修正幅度 ≤ 一档难度差（轻规则 ±4 封顶） |
| `branch_key` | 分支钥匙 | 打开道具边，改变故事图形状 | **必须声明 `unlocks`**；校验器与道具边交叉指认 |
| `codex` | 图鉴/Lore | 集齐系列解锁背景条目与隐藏入口 | 必须归属已注册的图鉴系列 |

组合规则：

- 可多身份叠加（如织命者残简 = `codex` + `branch_key`），且鼓励——四重身份递进正是收集驱动分支拓扑的设计意图（白皮书 §8）；
- `branch_key` 开启的边必须有非钥匙替代路径（`fallback` 或绕行），钥匙是捷径与加料，不是铁门——例外须评审；
- 剧情道具（命骰类）标记 `quest: true`：不可丢弃、不占负重、不出售。

## 2. 稀有度与投放

| 稀有度 | 对应身份 | 投放原则 |
|---|---|---|
| 普通 | stat | 商店 / 常规战利品 |
| 精良 | stat / check_mod | Boss 战利品、检定成功路 |
| 稀有 | branch_key | 支线链深处、隐藏拾取 |
| 信物 | codex（+branch_key） | 系列化分散投放：主线 ×1、隐藏点 ×1、Boss ×1、多周目 ×1（campaign01 残简模式为模板） |

获取即写板（`give_item` 效果 + 事件流），背包只是状态板 `global.inv` 的视图。

## 3. 图鉴系列划分规则

- **系列归世界观层定义**（`../story/01-世界观-抄本纪元.md` §9 四大系列），内容包只贡献条目并在 lore.json 声明系列归属；
- 新系列立项条件：≥6 条目规模、有明确的集齐奖励、与既有系列主题不重叠；
- 条目解锁来源必须在 nodes.json 中可查（`lore` 效果或隐藏拾取点），保证"集不齐"永远可追溯为"还有内容没玩到"。

## 4. 集齐奖励形式（白名单）

| 奖励形式 | 示例 | 状态 |
|---|---|---|
| 隐藏剧情线 | 织命者残简集齐 → 揭示褪墨真相 | ✅ |
| 隐藏战役/形态 | 被撤销者名录 → 解锁"追忆"战役（强制竖屏） | ✅ |
| 外观 | 命骰考 → 骰子皮肤 | ✅（纯演出，06 文档 §3） |
| 声望/折扣 | 烬港风物志 → 烬港声望与商店折扣 | ✅ |
| **数值强度** | — | ❌ 永久禁止（06 文档 §4 付费禁区同源：收集也不卖数值） |

集齐判定：系列条目全解锁事件触发，结算走标准效果词汇表，奖励内容走普通内容包校验管线。

外观类奖励到账细化（v1.1）：集齐奖励为骰子皮肤时，点亮 = 写外观旗标 `global.cosmetic.owned.<skin_id>`（07 文档 §3 v1.2，仅 system 可写），系列集齐判定聚合**全部已加载内容包**的 lore 条目（条目可跨包贡献，如谜回廊包贡献命骰考条目）；系列 id 以 `../tech/02-内容包格式规范.md` §10 注册值为准（命骰考 = `fatedie_study`）；皮肤与"系列 → 皮肤"映射登记在运营侧注册表 `packs/_ops/cosmetics.json`（06 文档 §7）。
