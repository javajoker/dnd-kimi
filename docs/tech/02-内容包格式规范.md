# 内容包格式规范

> 版本：v0.1（讨论稿）
> 关联文档：`01-技术方案讨论稿.md`、`../framework/01-框架白皮书.md` §10、`../framework/05-规则系统框架.md`、`../framework/06-商业化框架.md`
> 范围：内容包（战役 / 故事线 / 子游戏）的数据格式定义——目录结构、各文件 Schema、边与效果的条件 DSL、版本与权利声明、校验规则。**这是内容数据与框架运行时之间的契约。**
> 首个实例：`../story/campaign01/`（《烬港残页》），制作流程见 `03-内容包制作操作指南.md`。

## 1. 包目录结构

```
<pack_id>/
├── manifest.json      # 包声明：身份、版本、依赖、模式、权利门槛（§2）
├── nodes.json         # 故事节点图：节点 + 五类边（§3、§4）
├── events.json        # L3 任务/事件清单：触发、目标、结算写板（§5）
├── encounters.json    # L4 遭遇定义（§6）
├── items.json         # 道具表：四重身份（§7）；可使用道具的 use 块见 `04-资源与效果系统.md` §4
├── flags.json         # 旗标声明：写入点 / 读取点台账（§8）
├── characters.json    # 角色/同伴/NPC（可选；Schema 见 `04-资源与效果系统.md` §2）
├── skills.json        # 技能表（可选；同上 §3）
├── effects.json       # 效果/修饰器（可选；同上 §5）
├── enemies.json       # 敌人表（可选；同上 §1）
├── endings.json       # 结局分型（仅战役包）（§9）
├── lore.json          # 图鉴 Lore 条目（§10）
└── texts/             # 文本资源（预留 i18n；首版可缺省，文本内嵌于各文件）
    └── zh-CN.json
```

规则：文件名固定、大小写敏感；校验器对未知文件报警但不拒绝（向前兼容预留）。

## 2. manifest.json

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| pack_id | string | ✅ | 全小写蛇形；同时是状态板命名空间前缀（白皮书 §4.3） |
| name | string | ✅ | 显示名（如「烬港残页」） |
| pack_type | enum | ✅ | `campaign` / `arc` / `subgame` |
| pack_version | int | ✅ | 单调递增整数 |
| min_framework_version | string | ✅ | 所需最低框架版本（PRD F5.2） |
| rule_pack | object | ✅ | `{ "id": "light", "min_version": 1 }`（05 文档 §5 战役级绑定） |
| presentation | object | ✅ | 模式声明，见 §2.1 |
| namespace | string | ✅ | 必须等于 pack_id（防呆冗余，校验器比对） |
| recommended_level | [int,int] | 战役必填 | 推荐等级区间 |
| estimated_hours | string | 否 | 预计时长文案 |
| node_budget | int | 战役必填 | 节点预算，校验器核对实际节点数 |
| entitlement | object | 否 | 权利门槛声明（硬门槛），见 §2.2；缺省 = 随本体权利 |
| monetization | object | 否 | 付费策略参与声明（呈现与运营位依据），见 §2.3；缺省 = 随本体策略 |
| loadout | object | 否 | 整备配置（09 文档 §9.1），见 §2.4；缺省 = 不启用整备 |
| subgame | object | 子游戏必填 | 变体声明块，见 §2.5 |

### 2.5 subgame（子游戏声明块）

```json
{
  "rules_override": { "arena_mode": true },
  "gold_reward": [15, 25, 40],
  "stat_keys": ["wins", "best"]
}
```

- `rules_override`：**对象形态**（键值覆盖），规则包逐项应用；值为字符串时视为规则包 ID（整包替换，向后兼容）；
- 扩展字段（如 `gold_reward` 场次奖励表、`stat_keys` 战绩键清单）按 §11"新增字段一律可选"登记于此，子游戏运行器数据驱动消费；
- **奖励归属**：子游戏奖励写本包命名空间（胜场/纪录旗标、`arena.xp_earned` 等）；道具/金币等互通奖励经效果词汇写 `global.inv` / `<ns>.gold`；**跨包成长汇总**（子游戏经验计入玩家成长）待 tech/04 成长系统定稿——子游戏不得直接写他包命名空间（07 §3）；
- 子游戏与其他内容包一样，可独立声明付费策略（§2.3）与整备配置（§2.4）。

### 2.1 presentation（战役模式声明，白皮书 §7.1）

```json
{
  "mode": "choice",
  "forced": { "SL-0": "time", "SL-3": "time" },
  "recommend": { "N4-1": "space" }
}
```

- `mode`：`space`（横屏空间）/ `time`（竖屏时间）/ `choice`（双模式可选，入口呈现模式分支）；
- **`choice` 缺省**：玩家未做选择时缺省 `time`（叙事流优先、单手友好）；
- `forced`：按幕（故事线 ID）强制某形态——强制本身是叙事手段，入口以叙事化包装呈现理由；
- `recommend`：节点级推荐（如最终 Boss 推荐横屏），不强制。

### 2.2 entitlement（权利门槛，06 文档 §2）

```json
{ "requires": ["entitlement.campaign01"] }
```

- 值为状态板全局权利变量列表，全真才解锁；**缺省 = 随本体权利**（本体买断则免费，本体 F2P 则看运营投放）；
- 未解锁时战役入口呈现"锁定态"（06 文档 §3.1），数据照常加载、不可进入；
- 这是**硬门槛**：内容包只声明"需要什么"，不声明"怎么获得"（点亮方式归运营，06 文档 §3.2）。

### 2.3 monetization（付费策略参与声明）

```json
{ "strategies": ["dlc", "subscription", "cosmetic"] }
```

- 合法值：`buyout_component`（随本体买断）/ `dlc` / `subscription` / `cosmetic` / `free`；
- 语义：本包**参与**哪些付费策略——供战役入口锁定态呈现、主屏运营位与订阅权益区展示；实际门槛永远以 `entitlement.requires` 为准；
- **一致性校验（V9 扩展）**：`strategies` 含 `dlc` 时 `entitlement.requires` 必填；`strategies` 为 `["free"]` 时不得声明 `requires`；两者冲突即拒绝加载；
- 策略调整（如 DLC 转订阅包含）由运营侧改变权利点亮方式完成，**本字段与门槛声明无需改动**——除非策略语义本身变化（如免费包改为 DLC），此时走内容包版本递增。

### 2.4 loadout（整备配置）

```json
{ "enabled": true, "item_slots": 2, "skill_slots": 2, "respec": false }
```

- `enabled`：战斗遭遇进场前是否进入整备界面；`item_slots` / `skill_slots`：携带上限；`respec`：整备是否允许重洗已分配属性点；
- **限制与否、槽位数量全部由本配置决定**——框架只执行，不做硬编码假设（对应"是否加限制根据游戏配置文件确定"）；
- 战役级声明，`encounters.json` 单条遭遇可用同名块覆盖（如 Boss 战收紧槽位）；
- 整备选择写入事件流（`loadout.confirm`）。

## 3. nodes.json：节点

```json
{
  "acts": [
    { "id": "SL-0", "title": "潮醒", "mode": "forced_time", "role": "教学" }
  ],
  "nodes": [
    {
      "id": "N0-2",
      "act": "SL-0",
      "type": "check",
      "title": "消失的码头名",
      "summary": "检定教学：辨认正在褪去的码头名",
      "on_enter": [],
      "edges": [ "……见 §4……" ]
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✅ | 包内唯一；沿用战役书编号（N0-1 / R3 / N2S-2……），便于与设计稿对照 |
| act | string | ✅ | 所属故事线（幕）ID，须存在于 acts |
| type | enum | ✅ | `scene`（演出）/ `hub` / `check` / `battle` / `dialog` / `explore` / `rest` / `branch` / `ending` |
| title / summary | string | ✅ | 显示文本 |
| encounter | string | 条件 | 关联 encounters.json 中的遭遇 ID（战斗/迷宫/休整节点必填） |
| on_enter | effect[] | 否 | 进入节点即结算的效果（写旗标、推时钟……），DSL 见 §4.6 |
| on_complete | effect[] | 否 | 节点全部边结算完成、离开前结算（如 N2S-3 两条选择边均发印戒） |
| edges | edge[] | ✅ | 出边；终章节点可为空数组 |

任何类型的边都可附带 `label`（显示文案）与 `requires`（额外门槛条件，§4.6）。

## 4. 边与条件 DSL

五种设计边（白皮书 §5.1）统一编译为 **条件 + 目标 + 效果** 结构；`type` 是语义标签，供 UI 呈现与校验器分类检查，运行时只有条件求值。

### 4.1 选择边 `choice`

```json
{ "type": "choice", "label": "献出一段自己的记忆", "to": "N2-C",
  "effects": [ { "write": "blank_memory", "value": true }, { "clock": -2 } ] }
```

### 4.2 检定边 `check`

```json
{ "type": "check", "skill": "perception", "difficulty": "easy",
  "success": "N0-3a", "failure": "N0-3b",
  "success_effects": [ { "write": "seen_fading", "value": true } ],
  "failure_effects": [ { "xp": 50 } ] }
```

- `skill`：技能名，合法值由所绑定规则包定义（轻规则包：力/敏/智三维衍生技能表）；
- `difficulty`：三档 `easy / medium / hard`（轻规则）；
- `alt_pass`：可选的替代通过方式（如 `{ "pay_gold": 200 }`，对应设计稿"检定或支付金币"）；
- 成功与失败允许指向同一节点，此时差异必须体现在 `success_effects` / `failure_effects`（如 N2S-1 失败罚时 1 格）；
- **校验硬规则**：`failure` 必填——"失败即分支"（白皮书 §5.2），校验器拒绝无失败路的检定边。

### 4.3 道具边 `item`

```json
{ "type": "item", "item": "half_tide_table", "to": "N2G-2b", "fallback": "N2G-3" }
```

持有则显形通往 `to`，否则走 `fallback`（可缺省 = 该边不显形）。

### 4.4 时间边 `doom_clock`

```json
{ "type": "doom_clock", "at": 2, "to": "N1-7", "once": true }
```

时间钟（`global.doom_clock` 或声明的局部钟）到格自动触发；`once` 防重复触发。

### 4.5 声望 / 倾向边 `reputation`

```json
{ "type": "reputation",
  "requires": { "rep.scriptorium": { "<=": 0 }, "rep.uninked": { "<=": 0 }, "rep.salvage": { "<=": 0 } },
  "to": "N2L-1" }
```

隐形门槛；条件满足时选项才出现。

### 4.6 通用条件与效果词汇表

条件（可用于 `requires` 与结局条件）：

| 键 | 值形式 | 含义 |
|---|---|---|
| `flag.<id>` | bool | 旗标（包内旗标省略前缀，自动解析为本包命名空间） |
| `rep.<faction>` | `{ ">=": n }` 等 | 声望阈值 |
| `clock` | `{ ">=": n }` | 纪元钟格数（`global.doom_clock`） |
| `clock.<id>` | `{ ">=": n }` | 局部钟格数（自动解析为 `<ns>.clock.<id>`；求值器实现随 TP1 内容加载接入） |
| `item.<item_id>` | bool 或 `{ ">=": n }` | 持有 / 持有数量 |
| `alignment` | `{ "ink_gt": 50 }` / `{ "blank_gt": 50 }` | 倾向轴（墨守/留白过中线） |
| `bond.<npc>` | `{ ">=": n }` | 指定队友羁绊值 |
| `bond_max` | `{ ">=": n }` | 任一队友羁绊值（结局条件常用） |
| `all` / `any` | 条件数组 | 组合 |

效果（可用于 `effects` / `on_enter` / 结算）：

| 键 | 含义 |
|---|---|
| `write` + `value` | 写旗标 |
| `clock` / `clock.<id>` | 纪元钟 / 局部钟增减（负值延缓） |
| `rep.<faction>` | 声望增减 |
| `alignment` | 倾向滑动 |
| `give_item` / `remove_item` | 物品增减 |
| `xp` | 经验 |
| `bond.<npc>` | 羁绊增减 |
| `lore` | 解锁图鉴条目（写入 `global.lore` 集合并产 `lore.unlock` 事件，07 文档 §2） |

## 5. events.json（L3 任务/事件）

```json
{
  "id": "ink_rain_raid",
  "name": "墨雨夜袭",
  "trigger": { "type": "doom_clock", "at": 2 },
  "objective": "赢得 N1-7 午夜墨雨",
  "node": "N1-7",
  "settle": [ { "xp": 200 }, { "give_item": "ink_core" } ]
}
```

`trigger.type`：`auto`（随节点自动）/ `choice`（玩家选择链）/ `doom_clock` / `reputation` / `hidden`（隐藏条件，如独狼捷径）。

## 6. encounters.json（L4 遭遇）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 建议与节点同号（`N1-7`），多场同名遭遇加后缀（`R4-r`） |
| type | enum | `battle` / `escort` / `maze` / `rest` / `hybrid`（战斗+抉择） |
| mode | enum | `inherit`（随战役模式）/ `forced_time`（强制竖屏） |
| difficulty | enum | `easy` / `medium` / `hard`（轻规则三档） |
| max_units | int | 同屏单位上限；`forced_time` 遭遇校验器强制 ≤8（04 文档 §④.4） |
| party | array | 可选，出战队伍实例：`[{ "id": "pc", "ref": "player_blank" }]`，`ref` 指向 characters.json 条目，`id` 为本场实例 id（事件流单位标识）；缺省 = 引导层不自动组队 |
| enemies | array | 可选，出战敌方实例：`[{ "id": "boss", "ref": "ink_fiend" }]`，`ref` 指向 enemies.json 条目，同 `ref` 可多实例（`id` 互异）；Boss 的范围技能（含 `save` 豁免声明）随 enemies.json 条目挂载 |
| pos | object | 可选，战术格初始落位（如 `{ "allies": [[2,4]], "enemies": [[3,1]] }`）；**缺省时渲染层按阵营+先攻序确定性落位**——落位是纯呈现行为，不进事件流 |
| party_advantage | object | 可选，优势来源声明（11 文档 §3.1：来源由内容包声明）：`{ "flag": "witnessed_revocation", "rounds": 1 }`，旗标成立时全队攻击优势 `rounds` 回合 |
| escort | object | `escort` 类型必填，护送目标声明：`{ "unit": {…}, "survive_rounds": 3, "failure_effects": […] }`。`unit` 为内联友方 NPC 条目（字段同 enemies.json 条目：id/name/hp/ac/attrs/attack_mod/damage），运行时以 `kind=escort_npc` 入队：不占行动轮、不可被指令、HP 不跨遭遇持久化。胜负按 11 文档 §5「遭遇定义的目标达成」：护送对象存活满 `survive_rounds` 个完整回合**或**全歼敌人 = 胜；护送对象 HP 归 0 = **目标失败**（`objective_failed`，罚时替代全灭）——战斗即结束、无战利品/经验，按 `failure_effects`（效果 DSL §4.6）写板后仍走节点唯一出边（失败即分支，08 文档 §2）。敌方近战意图优先指向护送对象（打断仪式），范围效果照常覆盖全队 |
| maze | object | `maze` 类型必填，探索序列声明：`{ "beats": […] }`（04 文档 §④.3 房间类型的序列化呈现；完整格子迷宫留后续迭代）。2~3 个节拍，每拍一种：`{ "type": "check", "skill", "difficulty", "text", "success_effects"?, "failure_effects"? }`（检定房，修正 = 玩家属性+熟练，11 文档 §2/§3）；`{ "type": "loot", "item", "n"?, "text" }`（拾取房，`item` 须在 items.json 登记，V11）；`{ "type": "ambush", "skill", "difficulty", "enemy"?, "text", "failure_effects"? }`（伏击判定：检定失败吃 `failure_effects`；`enemy` 为演出用敌人引用，须登记，V11）。节拍效果走效果 DSL（§4.6），纳入 V4/V5/V11/V12 校验闭环；序列完成后回节点呈现其出边 |
| loot | array | 可选，胜利战利品：`[{ "item": "ink_core", "n": 1 }]`，`item` 须在 items.json 登记（V11 校验） |
| xp | int | 可选，胜利经验（11 文档 §6 成长表输入） |
| note | string | 设计备注（Boss 机制指针等，数值细则随轻规则包） |

## 7. items.json

| 字段 | 说明 |
|---|---|
| id / name | ASCII 稳定 ID + 中文显示名 |
| roles | 四重身份标签数组：`stat`（数值）/ `check_mod`（检定修正）/ `branch_key`（分支钥匙）/ `codex`（图鉴），可多选（白皮书 §8） |
| source | 投放点（节点 / 商店 / Boss 战利品 / 多周目继承） |
| unlocks | 开启的边或结局（分支钥匙必填，供校验器与道具详情提示用） |

## 8. flags.json

```json
{
  "id": "seen_fading",
  "name": "眼见为实",
  "type": "bool",
  "default": false,
  "writers": ["N0-3a"],
  "readers": ["R2", "history_scroll"]
}
```

旗标台账是**旗标闭环校验**的输入：声明的 writers/readers 与 nodes.json 实际读写比对，写入必有读取、读取必有写入（战役书 §10 检查项的工具化）。全局变量（`global.doom_clock`、`rep.*`、`alignment`、`bond.*`）不在此声明，归框架层。

## 9. endings.json

```json
{
  "id": "E3",
  "title": "新篇",
  "hidden": true,
  "conditions": { "all": [ { "item.codex_fragment": { ">=": 4 } }, { "any": [ { "bond.*": { ">=": 60 } } ] } ] },
  "content": "白页者成为新执笔者",
  "ngplus_hook": "解锁「执笔者」开局身份"
}
```

结局条件用 §4.6 条件 DSL；`default: true` 标记兜底的失败非终局结局（E4）。

## 10. lore.json

图鉴条目归属世界观四系列（`weaver_fragments` 织命者残简 / `revoked_registry` 被撤销者名录 / `fatedie_study` 命骰考 / `ashenport_local` 烬港风物志），条目声明解锁来源节点；系列集齐奖励在世界观层定义，包内只贡献条目。

## 11. 版本与兼容

- 三方版本解耦：框架 / 内容包 / 规则包各自递增；内容包只声明 `min_framework_version` 与 `rule_pack.min_version`；
- 包升级必须向后兼容进行中的存档：删除节点只允许在"无任何存档可达该节点"的判定下（校验器检查）；
- Schema 演进：新增字段一律可选；必填字段变更 = Schema 大版本 + 迁移器。
