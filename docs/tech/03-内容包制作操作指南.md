# 内容包制作操作指南：从战役书到可加载数据

> 版本：v0.1（讨论稿）
> 关联文档：`02-内容包格式规范.md`（格式契约，先读）、`../story/02-战役书-烬港残页.md`（首个实例来源）
> 范围：内容作者（策划/编剧）把一本定稿战役书转写为可加载内容包的操作流程。参照实例：`../story/campaign01/`。

---

## 1. 总流程

```
① 战役书设计定稿（story/ 层文档，含分支图自检）
   → ② 建包：目录 + manifest
   → ③ 节点图转写 nodes.json
   → ④ 五类边转写（边模板套用）
   → ⑤ 四张表转写（events / encounters / items / flags）
   → ⑥ 结局转写 endings.json（+ lore.json）
   → ⑦ 跑校验器（V1~V10 全绿）
   → ⑧ 仿真试玩 / 引擎内加载
```

转写是**翻译不是再创作**：数据文件中的节点 ID、边的走向必须与战役书逐条对应。转写中发现的图问题（死路、缺失败路），回到战役书修改并同步，不允许只在数据里偷偷修——两份真相以设计文档为准。

## 2. 战役书章节 → 数据文件映射

| 战役书章节 | 数据文件 | 说明 |
|---|---|---|
| §1 战役卡 | `manifest.json` | 逐字段直译 |
| §3 总体结构 | `nodes.json` 的 `acts` | 幕 ID、强制模式标注 |
| §4 节点图 | `nodes.json` 的 `nodes` | 一步一节，见 §3 |
| §5 旗标设计 | `flags.json` | 写入点/读取点台账直接来自设计表 |
| §6 任务/事件清单 | `events.json` | 一行一条 |
| §7 遭遇清单 | `encounters.json` | 一行一条 |
| §8 道具表 | `items.json` | 一行一条 |
| §9 结局分型 | `endings.json` | 条件转写为条件 DSL |
| §10 分支图自检 | 校验器输出 | 人工自检表由 V1~V10 自动化替代复核 |

## 3. 节点图转写（步骤 ③④）

### 3.1 编号规则

- 沿用战役书编号：`N<幕>-<序>`；幕二支线链加字母（`N2S-1`）；幕三房间保留 `R` 编号；
- 失败路、密道等派生节点用原号加小写后缀（`N1-2b`、`N2G-2b`）；
- **禁止在数据里改名**——编号是设计稿、数据、校验报错、试玩反馈之间唯一的公共语言。

### 3.2 五类边转写模板

| 设计稿写法 | 边 type | 必填字段 | 铁律 |
|---|---|---|---|
| `[选]` 救 / 不救 / 欺骗 | `choice` | `label` `to` | 效果进 `effects` |
| `[检·感知·中]` | `check` | `skill` `difficulty` `success` `failure` | **failure 必填** |
| `[物·半页潮汐表]` | `item` | `item` `to` | `fallback` 或省略（不显形） |
| `[时] 时间钟到 2 格` | `doom_clock` | `at` `to` | `once: true` 防重复 |
| `[声·三方声望均≤0]` | `reputation` | `requires` `to` | 隐形门槛，入口处无提示 |

设计稿里写在边上的叙事效果（"迟到：多花 1 格时间钟"）一律转写为该边的 `effects`（此处 `{ "clock": 1 }`），不写进节点——效果属于"走这条路"而不是"到这个点"。

### 3.3 收束与 Hub

- 多路汇入的收束节点（如 N2-C）：各自上游节点的边直接指向它，收束节点本身无需声明来源；
- Hub 节点（N1-1 广场）：`type: "hub"`，休整/商店功能是关联的 `rest` 遭遇，出边照常声明。

## 4. 四张表转写（步骤 ⑤）

以《烬港残页》为例：

- **events.json**：战役书 §6 十行 → 十条。`trigger` 的 `[时]`/`[选]`/`[声]` 标注对应 `doom_clock` / `choice` / `hidden`；
- **encounters.json**：§7 十四行 → 十四条。注意 `R3`/`R4-r`/`R5` 在强制竖屏幕，必须 `mode: "forced_time"` 且 `max_units` ≤8；
- **items.json**：§8 六行 → 六条。`roles` 填四重身份标签；分支钥匙必须填 `unlocks`，校验器据此交叉核对道具边引用的合法性；
- **flags.json**：§5 八行 → 八条。`writers`/`readers` 填节点 ID；全局变量（时钟、声望、倾向、羁绊）**不要**写进包内 flags。

## 5. 结局与图鉴（步骤 ⑥）

- 结局条件用条件 DSL 直译（"墨守倾向 > 中线" → `{ "alignment": { "ink_gt": 50 } }`）；
- 必须有且仅有一个 `default: true` 的兜底结局（E4）——校验器 V1/V5 依赖它证明无死路与时钟收束；
- 图鉴条目注明归属系列与解锁节点；跨包系列（织命者残简等）只贡献条目，不重复定义系列。

## 6. 校验与加载（步骤 ⑦⑧）

```bash
# 结构 + 图校验（V1~V10）
packlint docs/story/campaign01

# 仿真试玩：bot 随机/穷举走图，跑通全部结局
simulate docs/story/campaign01 --endings all --seed 42
```

> 工具随技术原型 TP1 交付（见 `01-技术方案讨论稿.md` §10）；在此之前以战役书 §10 人工自检 + 数据评审代替。

### 常见校验报错对照

| 报错 | 原因 | 修法 |
|---|---|---|
| V3 check edge missing failure | 检定边没写失败路 | 回战役书补失败路设计，再转写 |
| V4 orphan flag | 旗标有写入无读取（或反之） | 删旗标，或补读取点设计 |
| V5 clock unbounded | 时钟效果可突破 0~10 | 调整效果数值或补 E4 类兜底 |
| V7 namespace violation | 包内写了 `global.` 白名单外的键 | 改走包内旗标 + 事件中心联动 |
| V8 portrait unit overflow | 竖屏遭遇 max_units >8 | 拆遭遇或改遭遇模式声明 |
| V14 graft target missing | 支线 graft.into/graft.node 在目标包不存在 | 核对目标包版本与节点编号；graft 三字段（into/node/edge）缺一不可 |

## 6.1 支线包（arc）与子游戏的制作差异

- **支线（pack_type=arc）**：必须有 `graft` 块（tech/02 §2.6）——宿主包一个字符都不改，支线通过注入边挂进主图；
  节点图是"小弧线 + 收束边指回宿主节点"；不声明 endings（收束回主线即结局）；
  可直接引用宿主包角色/敌人/道具（合并视图解析），自有条目 id 不得与宿主冲突（V14）；
  lint 口径 = `lint_grafted`（合并视图跑 V1~V3/V11，本包口径跑 V4/V6~V9/V12/V13 + V14）。
- **子游戏（pack_type=subgame）**：自包含包（资源四表随包携带，arena 先例）；
  纯解谜子游戏 = explore 节点 + maze 节拍（`retry_on_fail`/`hint` 解谜房语义，tech/02 §6），
  `subgame.clear_as_win: true` 使抵达结局节点记 1 胜（无战斗子游戏的战绩口径，§2.5）。
- 双副本纪律不变：编写源（docs/story/&lt;arc&gt;/、docs/subgames/&lt;name&gt;/pack/）与运行副本（game/packs/&lt;id&gt;/）逐文件一致。

## 7. 文本与本地化

首版文本内嵌各文件（`title` / `summary` / `label` 字段）。`texts/` 目录为 i18n 预留：需要本地化时把文本抽取为键值（`texts/zh-CN.json`），节点内只留键。抽取是工具行为，不手改。

## 8. 评审清单（数据 PR 自检）

- [ ] 与战役书逐节对照，无擅自增删节点与边
- [ ] 节点编号与战役书一致
- [ ] 每条 `check` 边有失败路
- [ ] 分支钥匙道具的 `unlocks` 与图中 `item` 边互相指认
- [ ] flags.json 台账 = 战役书 §5
- [ ] 校验器全绿（或列明暂缓项与原因）
