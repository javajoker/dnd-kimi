# 资源与效果系统规范

> 版本：v0.1（讨论稿）
> 关联文档：`01-技术方案讨论稿.md` §6、`02-内容包格式规范.md`、`../framework/11-轻规则包-v1.md`
> 范围：角色、技能、道具、效果（修饰器）四类数值资源的**数据格式与叠加模型**——目标是"加资源 = 加数据行，调平衡 = 改数据值"，框架零改动。

---

## 1. 资源总览

| 资源 | 文件 | 归属 | 示例 |
|---|---|---|---|
| 角色定义 | `characters.json` | 内容包 | 玩家模板、同伴、NPC |
| 技能定义 | `skills.json` | 内容包（规则包可提供基础集） | 佩剑挥砍、墨术飞矢 |
| 道具定义 | `items.json`（02 文档 §7） | 内容包 | 墨核、补给药水 |
| 效果（修饰器） | `effects.json` | 内容包 | 墨核强化、护送祝福、中毒 |
| 敌人定义 | `enemies.json` | 内容包 | 墨魈、守页人 |

设计约束（承 02 文档）：文件名固定；新资源 = 新数据行，合法值集合（属性名、检定难度档、效果算子）由**规则包**注册，校验器按绑定规则包校验。

## 2. characters.json

```json
{
  "id": "companion_kelan",
  "name": "珂兰",
  "kind": "companion",
  "attrs": { "might": 0, "finesse": 2, "wits": 1 },
  "hp_formula": "10 + 2*level + might",
  "ac_formula": "10 + finesse",
  "proficiencies": ["history", "soothe"],
  "skills": ["ink_dart", "scribe_shield"],
  "bond": { "initial": 20, "personal_quest": "kelan_q1" }
}
```

- 公式为**字符串表达式**（白名单变量：attrs/level/熟练值），规则包求值——改规则包不改角色表；
- 玩家角色模板 `kind: "player_template"` 提供创建默认值（11 文档 §1 的 +2/+1/0）。

## 3. skills.json

```json
{
  "id": "inkbolt",
  "name": "墨术飞矢",
  "kind": "attack",
  "attr": "wits",
  "damage": "1d6",
  "uses_per_encounter": 2,
  "target": "enemy_single",
  "gesture": "path",
  "effects_on_hit": ["ink_burn_1"]
}
```

| 字段 | 说明 |
|---|---|
| kind | `attack` / `check` / `heal` / `utility`——决定走检定公式还是治疗/效用结算 |
| uses_per_encounter | 次数制（轻规则），休整恢复；`null` = 不限次 |
| gesture | 推荐手势（`tap`/`path`），仅呈现层提示，不影响合法性 |
| effects_on_hit | 命中后挂载的效果 ID 列表（§5） |

## 4. 道具的可使用化（items.json 扩展）

道具在 02 文档 §7 的四重身份之上，增加可选 `use` 块：

```json
{ "id": "heal_potion", "name": "补给药水", "roles": ["stat"],
  "use": { "timing": "bonus_action", "target": "ally_single", "effect": { "heal": "1d4+2" }, "consume": true } }
```

- `timing`：`action` / `bonus_action` / `out_of_combat`——与行动经济对齐（09 文档）；
- `consume: true` 使用后从 `global.inv` 移除（写板 + 事件流，同一切规则）。

## 5. 效果系统（修饰器叠加模型）

### 5.1 效果定义（effects.json）

```json
{
  "id": "ink_core_weapon",
  "name": "墨核淬刃",
  "target_attr": "attack_damage",
  "op": "add",
  "value": 1,
  "duration": "campaign",
  "stack": "refresh"
}
```

| 字段 | 合法值 | 说明 |
|---|---|---|
| target_attr | 规则包注册的可修饰属性（attack_damage / ac / hp_max / check_mod.<skill> / …） | 修饰什么 |
| op | `add` / `mul` / `override` / `clamp_max` / `clamp_min` | 怎么修饰 |
| duration | `encounter` / `rest` / `campaign` / `permanent` | 何时过期 |
| stack | `refresh`（同源刷新）/ `stack`（叠层，需 `max_stack`）/ `unique`（同 ID 唯一） | 叠加行为 |

### 5.2 求值管线（恒定顺序，无例外）

```
最终值 = clamp( override( mul( base + Σadd ) ) )
```

1. `base`：规则包公式的基础值；
2. `add` 桶：全部 add 修饰求和；
3. `mul` 桶：全部 mul 修饰连乘；
4. `override`：取**挂载时间最新**的一条（覆盖即唯一）；
5. `clamp_*`：最后钳位。

同一数值的求值顺序全局恒定——这是"同一事件流，双形态零差异"在效果层的保证；渲染层只读最终值。

### 5.3 溯源与撤销

- 每次效果挂载/过期/触发都进事件流（`effect.attach` / `effect.expire`），携带来源（道具/技能/节点）——历史卷轴可回答"这个 +1 是哪来的"；
- 效果只修饰数值，**不得直接写剧情旗标**（写旗标走效果词汇表，铁律不变）。

### 5.4 更新与平衡调整

- 资源表随内容包版本递增；进行中战役按绑定版本冻结（与规则包同策略）；
- 平衡性调整（改数值/次数/效果量）= 只改资源表数据，走内容包管线 V1~V10 校验，**不动框架**；
- 新增可修饰属性 = 规则包版本升级（数据结构的扩展位预留，11 文档 §1）。
