# 美术管线规范

> 版本：v0.1
> 关联文档：`02-内容包格式规范.md`（§1.1 text_ref 同构机制、§10 lore）、`04-资源与效果系统.md`（§1/§2 角色/敌人表）、`../framework/14-表现层与平台化清单.md` #7、`../framework/04-UI-UX设计文档.md` §4（ink/金墨配色）
> 定位：美术资产的**目录、命名、分辨率档、导入约定、占位兜底与内容包引用字段（art_ref）**唯一真相。实现服从本文档；新增资产类别/字段先补本文档再改代码（铁律同 tech/02 §0）。

## 1. 目录结构

```
game/assets/art/
├── units/       # 战斗单位图（敌我双方战场 token）
├── portraits/   # 角色头像（队伍芯片/角色名册/对话）
├── scenes/      # 场景/绘卷分层插画（预留，一期绘卷仍程序化 _draw 增强）
└── icons/       # 道具/技能/图鉴图标（预留）
```

- 资产入版本管理（与 fonts/audio 同口径）；运行时经壳层 `ArtLoader`（`shell/ui/art_loader.gd`）`Image.load_from_file` 直读 PNG——与 `AudioStreamWAV.load_from_file` 同通道，免导入管线、无头可测、缺文件静默兜底；
- 首批资产由 `game/tools/gen_art.py` 程序化生成（纯 Python 标准库，零外部版权，固定种子可复跑逐字节一致）；美术稿替换时同名覆盖即可，热点/引用键不动（与 12 §5 绘卷落位同思路）。

## 2. 命名规范

```
<类>_<id>_<分辨率档>.png
```

- `<类>` = 目录名单数：`unit` / `portrait` / `scene` / `icon`；
- `<id>` = 内容包条目 id（characters/enemies/lore 的 `id`，小写蛇形）；
- `<分辨率档>` = 像素边长整数（见 §3）；
- 例：`units/unit_ink_fiend_128.png`、`portraits/portrait_companion_kelan_128.png`；
- 校验：测试层抽检目录内全部文件匹配 `^(unit|portrait|scene|icon)_[a-z0-9]+(_[a-z0-9]+)*_[0-9]+\.png$`（管线规范与生成物一致）。

## 3. 分辨率档

| 类别 | 1x（基线） | 2x（高清） | 说明 |
|---|---|---|---|
| 单位图 units | 64 | 128 | 战场 token；竖屏单位卡/横屏格内 |
| 头像 portraits | 128 | 256 | 队伍芯片用 1x 缩放显示，角色名册用 2x |
| 场景 scenes | 按屏宽 1080 基线 | 2160 | 预留（绘卷分层插画落地时冻结） |
| 图标 icons | 64 | 128 | 预留 |

- 一期只交付 1x/2x 中的**当前使用档**（单位 128、头像 128）；补档 = 同名加档文件，壳按 `ArtLoader.texture_for(ref, tier)` 取档；
- 缺档回退：请求档缺失时回退已存在的最大档，再缺 = 无图兜底（§5）。

## 4. 导入约定

- 一期资产（程序化剪影，边缘含抗锯齿渐变）：**filter on（平滑）**——`ImageTexture` 默认线性过滤，不做像素风最近邻；
- 后续若引入像素风资产：在本文档登记该子集并改用 filter off（`ImageTexture` 创建后由壳层统一设置，渲染层对规则档位无感铁律不变——过滤模式是资产属性，不进 core）；
- 透明底 PNG（RGBA），剪影主体不透明度 100%，描边/微光允许半透明。

## 5. 占位图规则（无图兜底）

- **运行时缺图一律静默回退，不拒绝加载**（与 tech/02 §1.1 text_ref 键缺失同口径）：`ArtLoader.texture_for` 返回 `null`，壳层保持现状兜底——单位 = 色块+单字 token，头像 = 纯文本芯片；
- 断链属数据缺陷，由测试层断言兜底（已声明 art_ref 的条目其目标文件必须存在且可加载）；
- 绘卷等纯程序化呈现层无外部资产依赖，本身即兜底。

## 6. art_ref 字段约定（与 text_ref 同构）

- 内容包 `characters.json` / `enemies.json` / `lore.json` 条目可声明可选字段 `art_ref`；
- **值格式**：`"<类别目录>/<id>"`（不含类名前缀、分辨率档与扩展名），例：`"art_ref": "units/ink_fiend"`；
- **解析**：`res://assets/art/<类别目录>/<类名>_<id>_<档>.png`（§2/§3），由 `ArtLoader` 统一拼路径；
- **语义**：纯呈现引用——不进图遍历、检定与事件流判定（与 text_variants 同口径）；core 只做数据透传（BattleDef 组装进单位字典），不引用渲染 API；
- **作用域**：`art_ref` 是**包内资源键**，解析锚点是框架 `res://assets/art/`；内容包自带美术目录的合包形态（PCK 内 art/ 合并视图）待首个带图支线包落地时补写本节；
- **引用完整性**：已声明的 art_ref 其文件必须存在、可加载、尺寸命中 §3 档位——测试层抽检（同 text_ref 完整性断言口径）。

## 8. 壳层接入口径

- 竖屏（`shell/portrait/`）：单位卡 `Button.icon` 显示 art_ref 图像（展开居中、文字压上带阴影）；队伍芯片 = 头像 TextureRect + 文本（HBox）；
- 横屏（`shell/landscape/`）：格内 token 先铺 TextureRect（等比居中）再压 HP 文本；死亡/倒地变暗作用于图像与底色同口径；
- 两壳同一 `ArtLoader`（禁止复制"横屏版/竖屏版"加载逻辑）；无 art_ref 或加载失败 = §5 兜底；
- 主屏绘卷：一期不引外部图，`_draw` 程序化分层增强（棚顶灯光点、塔顶灯窗与光束、水面波光点），呼吸/褪墨度驱动口径不变（12 §5）。
