## 缺口（实现 < 文档）

### G1 【P1 · 阻塞】主屏 → 角色界面脚本崩溃 + 软锁（04 §5 ⑦ 角色界面出口列）
- **现象**：主屏点"角色"→ `push_error: 战斗定义组装失败（campaign01/）：遭遇 '' 未在 encounters.json 登记` → `SCRIPT ERROR: Invalid access to property or key 'party' on a base object of type 'Dictionary' (main.gd:734)`；界面停留在空白"角色"屏（无任何角色卡/成长区），"返回"按钮无效——**玩家软锁，只能杀进程**。截图证据：`/tmp/audit_char_bug.png` 与 `/tmp/audit_char_after_back.png`（按返回前后两图完全一致 = 界面卡死）。
- **根因**：`_show_character()`（main.gd:727-735）调 `_battle_def({})`，后者以 `_encounter_id`/graph.current_id 组装战斗定义；主屏场景 current_id 为空或非战斗节点 → fail-fast 返回 `{}` → `["party"]` 崩。崩溃点在 `_swap(screen)` 之后、`screen.bind` 与 `back_requested.connect` 之前 → 返回信号从未连接。
- **触发域**：战役开始前必崩；战役中回主屏时当前节点为非战斗节点（绝大多数节点）必崩；仅当前节点恰为 battle 节点时幸免。**玩家必踩**。
- **测试盲区**：tests/run.gd:3038 直接用构造好的 party 数据 bind ScreenCharacter，从未走 `_show_character` 的 `_battle_def({})` 路径 → 872 断言全绿也盖不住。
- **附带**：空白角色屏底部残留一行被截断的占位文本"（法术位 / 装备槽 / 状态效果 （最小版：要素随内容接…"——溢出屏幕右缘，布局穿帮。
- **建议修法**：角色界面队伍数据不应复用"当前遭遇战斗定义"通道——改为从 characters.json + 成长簿记（Growth）独立组装展示模型；同时把 `back_requested.connect` 移到 bind 之前（防御）。

### G2 【中】RNG 内部状态经 JSON 存档往返丢精度——读档后骰序偏离（07 §4.1；rng.gd"恢复后续掷与中断前完全一致"承诺）
- **证据**（探针 /tmp/rng_probe.gd）：`Rng.save_state()` 产出 `state=3619339438595917384`（int64）；经 JSON 写盘读回变 `3619339438595917312.0`（float，尾数丢失 >2^53）；`load_state` 后连续 5 骰 `[7,15,13,19,13]` vs 原序列 `[7,1,16,17,2]`——**不一致**。
- **影响**：单人游玩无感（骰子本来随机），但违反 07 §4.1 快照承诺与 tech/01 §5.2"事件流+种子=可完整复盘"——跨存档点的复盘与双壳一致性审计在含读档的会话中失效。
- **测试盲区**：test_rng 的 save/load 断言是内存内往返（不过 JSON），test_save_system 不断言读档后骰序。
- **建议修法**：state 以十进制字符串序列化（或拆双 32 位 int），迁移链加 v2→v3；补"JSON 磁盘往返后骰序一致"断言。
